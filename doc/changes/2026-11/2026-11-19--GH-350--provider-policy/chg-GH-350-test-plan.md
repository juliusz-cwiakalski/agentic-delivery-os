# Test Plan - M4-S4: Declarative provider policy — quota, peak, cost routing

## 1. Scope and Objectives

This change makes provider selection a property of configuration, so the risk is not a missing command — it is a policy that *looks* correct while one of its independent truths is false. Each truth is proven as a comparison a test runs, never as a prose claim. **First, a declared clock is the provider's clock.** A window declared in a named zone is evaluated in local seconds-of-day through one injected `ProviderZonePort`, and its expiry is the earliest instant at or after the declared local end across spring-forward, fall-back, the southern hemisphere, a no-transition span, the buffer edge, a skipped local second and a repeated local second (`TC-ZONE-005`..`TC-ZONE-008`); the engine gate, the profile gate and the daemon watcher are asserted equal on one fixture table, so a second boundary implementation fails by name (`TC-ZONE-008`); a name longer than the declared `PROVIDER_ZONE_NAME_MAX_LENGTH = 64` is the declaring surface's shape failure and a syntactically valid zone the runtime cannot resolve refuses `provider.peak.zone-unknown` before any evaluation with zero parks, zero announcements and a byte-identical state snapshot (`TC-ZONE-002`, `TC-ZONE-003`), and a composition that supplies no port refuses a non-UTC declaration rather than evaluating it as UTC (`TC-ZONE-004`). **Second, a ceiling stops a spawn instead of reporting it afterwards.** A typed `provider.budgets` map validates fail-closed naming the field (`TC-BUD-001`); one verified ref-scoped spend read projects every declared scope, so the read count is exactly one at any budget count (`TC-BUD-007`); a window crossing parks at exactly `newestAtMs + windowSeconds x 1000`, strictly future by construction (`TC-BUD-003`, `TC-BUD-004`); a ticket crossing is a failed entry with no park, no expiry, a `warning` announcement and a terminal `provider.budget.exceeded` refusal that names the figure and the fact that the ceiling cannot reopen (`TC-BUD-005`, `TC-BUD-006`); a damaged read refuses instead of reading as clear while verified-empty measures zero (`TC-BUD-009`); and no chain configuration makes a paid entry selectable while a subscription entry is budget-parked (`TC-BUD-010`). The limit is documented as well as enforced: the specification and the operator guide state the one-spawn-increment pre-spawn bound and no document claims a hard real-time cap (`TC-DOC-002`, `TC-DOC-003`).

**Third, "per-project" is behaviour that already exists.** The five provider element kinds resolve through the delivered layers, project-local beats project-committed, record maps merge by child name while lists replace whole, every effective value reports its winning origin, an invalid repository layer refuses instead of falling back, and no `provider.projects.*` key exists anywhere (`TC-CFG-001`..`TC-CFG-011`). **Fourth, the shell path is off the delivery path, not merely deprecated.** `provider resolve`, `provider quota`, `provider watch status` and `provider simulate` resolve policy with both legacy paths absent and again with them present-but-inert while a recording file-access stub observes zero reads (`TC-INDEP-001`..`TC-INDEP-003`), and every policy input is a typed configuration value carrying names only (`TC-INDEP-004`). **Fifth, the verification bar is executable.** `provider simulate --fixture` composes the delivered engine with fixture seams and `persist: false`, so the payload carries `stateWrites: 0` and the resolve keys equal what `resolve` returns for identical facts (`TC-SIM-004`); two runs are byte-identical and object key order changes nothing (`TC-SIM-006`); throwing credential, transport, state and spawn fakes prove zero effect by failing if reached (`TC-SIM-003`); and the fixture schema has no value field, so a credential-shaped fixture is a refusal rather than a redaction (`TC-SIM-002`).

**Sixth, the bridge off shell policy is safe by construction.** The migration parses legacy input as data under an assignment-only subset, refuses the whole run for each construct outside it with empty stdout and no write (`TC-MIG-003`), proves nothing ran with a canary whose destructiveness is itself demonstrated by a positive control (`TC-MIG-004`), classifies a credential-shaped name before its value and scans every output surface and written file for the canary (`TC-MIG-005`), maps literally from a closed table and discloses everything else by name (`TC-MIG-006`, `TC-MIG-007`), and creates at most one new document without ever merging (`TC-MIG-010`). **Seventh, an aged reading is a third state, not a false clear or a false outage.** The predicate is stale exactly at `ageSeconds >= maxAgeSeconds` under `floor` (`TC-WFRESH-002`), the view reports `watch-stale` with the observed instant, the age and the bound (`TC-WFRESH-003`), the condition enters no park cause, condition kind, skip reason or announcement code (`TC-WFRESH-004`), a derived park is clamped to the bound and is never created once the bound has passed (`TC-WFRESH-005`, `TC-WFRESH-006`), and the live composition reads at age zero (`TC-WFRESH-007`).

**Eighth, the conformance cost is paid in the same change.** The `provider` kind holds sixteen rows, the table 167, the documented table 166, the arithmetic `+133`, the two-segment allowlist 66 and the result-code corpus at its declared 84 rows — 59 true-positive and 25 false-positive (`TC-CONFORM-001`, `TC-CONFORM-002`); the vocabulary is exactly six condition kinds, eight park causes, nine skip reasons, thirteen announcement codes, fourteen park evidence fields, seventeen announcement evidence fields and one six-value watch set (`TC-CONFORM-003`, `TC-CONFORM-004`); the family keeps its five members and gains two, with help coverage agreeing in both directions and the reference page carrying `--help` and `--version` (`TC-CONFORM-006`); and the count-bearing pages carry 167 / 166 / 66 / `+133` while no page keeps an outgoing value or a retired UTC-only, non-UTC-out-of-scope, or shell-dependency statement as current truth (`TC-DOC-001`..`TC-DOC-005`).

The plan is deliberately adversarial about the failure modes this change names. **A DST matrix that cannot fail**: every cell asserts the resulting instant against an independent expectation derived from the declared rule, and the negative control re-runs the same matrix against an implementation that resolves the offset once at `now` — the spring-forward cell must then disagree (`TC-ZONE-005`). **A boundary-equality claim proven by three calls**: the same fixture table drives the engine, the profile gate and the watcher, so a shared-function claim that is only a comment fails on the first table row (`TC-ZONE-008`). **A zero-write claim proven by a read**: every refusal, every simulation and every migration asserts state-root bytes, `mtimeNs`, record absence and every written path (`TC-BUD-008`, `TC-SIM-003`, `TC-MIG-010`). **A one-read claim proven by an armed counter**: the injected totals port counts calls, so a per-budget re-read reports N instead of 1 (`TC-BUD-007`). **A credential firewall proven non-vacuously**: the canary scanner is itself driven over a planted string, so a scanner that never fires is a failure rather than a pass (`TC-MIG-005`). **A no-execution claim proven by a positive control**: the same construct that must not run is run through a real shell in the control arm, so the absent canary means "not executed" rather than "not looked for" (`TC-MIG-004`). **An inventory gate that cannot pass on an empty corpus**: every count is asserted exactly and by name in both directions, and each guard ships its mutant (`TC-CONFORM-003`, `§4.3`).

This document is a verification map, not an execution claim: nothing was run against a new implementation at authoring time, and phase ownership belongs to `chg-GH-350-plan.yaml`, authored in phase 4 after this plan. All 30 acceptance criteria are covered by at least one named case; there are no TODO rows and no orphan cases. Four properties are observed through a declared substitute, one through a declared vacuity, and two through a declared emptiness, each recorded in §3.5 rather than smoothed over. The two v1.0 review findings and the three underspecified values are resolved by spec v1.1 and recorded as resolutions in §8.3 (`OQ-TP-3`, `OQ-TP-4`, `OQ-TP-5`, `OQ-TP-7`, `OQ-TP-9`). What remains open is recorded rather than smoothed over: `OQ-TP-1`/`SEAM-TP-1` (where the injection point lives), `OQ-TP-2`/`SPEND-TP-1` (the window-scope oracle), `OQ-TP-6`/`VAC-TP-1` (a clause no spec version can make exercisable) and `OQ-TP-8` (the composed-`config` acceptance mechanism). `NOEXEC-TP-1`, `DOC-TP-1` and `EMPTY-TP-1`/`EMPTY-TP-2` remain declared bases, not gaps.

### 1.2 Out of Scope & Known Gaps

- [OUT] Windows crossing local midnight, per-window calendars, holiday or date rules, and any fixed numeric UTC-offset declaration form: the delivered no-crossing rule is asserted as read in local seconds, and no case declares a crossing window (NG-1, NG-2).
- [OUT] A vendored tz table, a pinned tz-data dependency, or a network zone lookup: no case installs or reads one. The adapters port is exercised against the runtime's own zone data for a known zone and the reduced-data posture is exercised by a syntactically valid name the runtime cannot resolve (`TC-ZONE-003`), never by replacing the host's zone database (NG-3).
- [OUT] Performance, latency and read-cost measurements: the read count is asserted exactly (`TC-BUD-007`) but no suite times a ledger read; RSK-4's revisit trigger is a judgement, not a threshold (NG-4).
- [OUT] A hard real-time cap, mid-spawn interruption, retroactive charge-back, or any persisted budget counter, state record kind, derived document, per-lane dimension or per-role dimension (NG-4, NG-5).
- [OUT] A project registry, project key, host-store policy, per-queue policy, or policy inheritance between repositories: `TC-CFG-006` asserts the surface is absent, and `TC-CFG-011` asserts the boundary is declared; no case drives M4-S5 behaviour (NG-6).
- [OUT] Any watch-driven admission gate, snapshot retention, cache, background refresher, scheduler, daemon tick or new watch command: `TC-WFRESH-008` asserts the absence structurally (NG-7).
- [OUT] Hook execution, emulation or import; writing, moving or deleting a legacy file; merging a proposal into an existing document: the refusal and the immutability are asserted, the capability is not (NG-8; `TC-MIG-010`, `TC-MIG-015`).
- [OUT] A textual diff between simulations, a `simulate --against` comparison and a fixture generator: parity is a test-side comparison, and no command surface is asserted for either (NG-9).
- [OUT] A new alarm kind, notification channel, event topic, subscription, scheduler or persisted alarm state: the burn-rate alarm is re-run as a control only (NG-10; `TC-BUD-016`).
- [OUT] A new command family, a new state record kind, a new store write path and a new environment variable: `TC-CONFORM-006` asserts the family and `TC-CFG-001`'s emptiness arm asserts the environment layer (NG-11).
- [OUT] Agent-prompt or command-definition changes, shell-wrapper rewrites, install/release/packaging changes: no case drives them; `pnpm check:prompt` and the install lifecycle are controls that must stay green with no edit (NG-14).
- [OUT] A credential value anywhere: no fixture carries one except the deliberately hostile canary fixtures of `TC-MIG-005`, which assert the value *cannot* appear (NG-12).
- [OUT] `watch-stale` as everyday detection: the live path has zero age by construction, and the documentation claim is asserted in the negative (`TC-WFRESH-007`, `TC-DOC-002`).
- [GAP-T1 — phase ownership belongs to the plan] `chg-GH-350-plan.yaml` owns phase boundaries, task ownership and per-phase test obligations. They are not asserted here; this plan declares what must be proven.
- [GAP-T2 — the environment and CLI projections of the provider precedence matrix are empty] **Resolved by spec v1.1 (C1)**: `AC-F3-1` now names the five layers a provider node can declare, and `AC-F3-4` carries the positive structural pin — a provider-shaped environment name refuses `config.environment.unmapped`, a provider-shaped flag refuses `config.key.unknown`, zero provider catalog nodes declare an `env` or `flag` source, and the change adds no environment variable or flag. The five-layer exercise plus the two refusal arms is now the **declared** reading rather than a narrowing; the row is retained as the record of the resolution, and the basis stays `EMPTY-TP-1` (`TC-CFG-001`, `OQ-TP-3`).
- [GAP-T3 — delivery-bound names] Module paths beyond spec §16's map, the internal names of the composition seams, and the exact wording of operator lines beyond their declared content are delivery-bound. The numeric caps are **no longer** in this class: spec v1.1 declares `PROVIDER_SIMULATE_FIXTURE_MAX_BYTES = 65536`, `PROVIDER_MIGRATE_SOURCE_MAX_BYTES = 65536`, `PROVIDER_MIGRATE_SOURCE_MAX_LINES = 2000`, `PROVIDER_MIGRATE_MAX_SOURCES = 64` and `PROVIDER_ZONE_NAME_MAX_LENGTH = 64`, and each is asserted at its `cap − 1` / `cap` / `cap + 1` refusal boundary (`TC-ZONE-002`, `TC-SIM-002`, `TC-MIG-011`). Behaviours, identities, exits, closed vocabularies, orderings and AC traceability are not delivery-bound.
- [GAP-T4 — CI-only gates are not observable before the pull request] `AC-F8-1`'s CI run is evidenced by the local invocation of the same script plus the delivered wiring assertions (`CI-TP-1`, `TC-CONFORM-001`, `TC-CONFORM-007`).
- [GAP-T5 — the NFR-to-AC binding for NFR-2 and NFR-8] **Resolved by spec v1.1 (C2)**: NFR-2 is linked on `AC-F1-2`, `AC-F5-2`, `AC-F5-3` and `AC-F6-1`; NFR-8 is linked on `AC-F2-2`, `AC-F2-3` and `AC-F8-3`. The plan's NFR mapping now shows the same bindings, and the cases already carrying the properties (`TC-BUD-014`, `TC-SIM-006`, `TC-MIG-012`, `TC-WFRESH-009` for NFR-2; `TC-DOC-002`, `TC-DOC-003` for NFR-8) are unchanged. Retained as the record of the resolution (`OQ-TP-4`, `COVER-TP-1`).

## 3. Coverage Overview

All 30 acceptance criteria map to at least one named case, and no case is an orphan. The plan carries **93 cases** in nine blocks: **11** zone cases (`TC-ZONE-001`..`TC-ZONE-011`), **16** budget cases (`TC-BUD-001`..`TC-BUD-016`), **11** configuration cases (`TC-CFG-001`..`TC-CFG-011`), **4** independence cases (`TC-INDEP-001`..`TC-INDEP-004`), **11** simulation cases (`TC-SIM-001`..`TC-SIM-011`), **15** migration cases (`TC-MIG-001`..`TC-MIG-015`), **10** watch-freshness cases (`TC-WFRESH-001`..`TC-WFRESH-010`), **10** conformance cases (`TC-CONFORM-001`..`TC-CONFORM-010`) and **5** documentation cases (`TC-DOC-001`..`TC-DOC-005`). The mapping is intentionally uneven in one direction: a criterion whose wording spans several independent observables is covered by more than one case (`AC-F2-2` by six, `AC-F6-4` by four, `AC-F1-2`, `AC-F5-3` and `AC-F7-3` by four each, `AC-F8-3` by five), while every case names at least one AC.

Every new describe title in a shared suite is prefixed `GH-350`, and no delivered label is renamed.

### 4.1 Hermeticity and determinism

Every case in this plan obeys six rules, and a case that cannot is a gap, not a warning:

1. **Scratch `HOME` and scratch config/state roots.** `HOME` is a `mkdtemp` directory under `tmp/tmpdir/` for every case that drives a command; brand path derivation is exercised through the resolver, never by writing the operator's home.
2. **Scratch project checkout.** Fixture checkouts carrying a project-committed and a project-local configuration document live under the scratch root; the fixture shape is created by the case, not committed as a nested repository.
3. **No mutation of live state.** `~/.jaiship`, `~/.jaiship-state`, and the operator's real `~/.<priorWorkingName>/config/profiles/` and hook path are never written **and never read**: a recording file-access stub proves the zero-read claim by recording attempts rather than by their absence.
4. **No real sleeps and no wall clock.** Time enters only through an injected clock; the zone port receives the instant it is given; the watch view receives `observedAtMs`. A case that advances time advances the injected clock and asserts a zero sleep counter.
5. **No live network and no live credential.** The quota transport is replaced by fixture facts for simulation and by a throwing fake wherever a network path would be wrong; credential outcomes are an enum; the operator's real credential store is never opened.
6. **`TMPDIR=$PWD/tmp/tmpdir` on every recorded gate command** (§6.3) and as the base for in-test scratch roots.

Determinism: no case asserts wall-clock timing; no case asserts directory-iteration order; no case asserts a diff against a moving base branch. Where the population is open-ended (the number of legacy files, the number of declared budgets), the assertion is a relation (`one per source`, `exactly one read`, `O(declared budgets)`), not a magic total.

### 4.2 Zero-write proofs

| Claim | Mechanism |
|---|---|
| A zone refusal wrote nothing | State-root snapshot (paths, sizes, `mtimeNs`, modes) before and after; no park record, no announcement record; stdout carries exactly the refusal; `TC-ZONE-003`. |
| A budget evaluation wrote nothing | The same snapshot plus a park/announcement write count of zero across the evaluation-only fixture, and an unchanged `mtimeNs` on the park document; `TC-BUD-008`. |
| A simulation wrote nothing | The snapshot plus four throwing fakes (state store, credential port, transport, spawn) that fail the case if reached, plus `stateWrites: 0` on the payload; `TC-SIM-003`. |
| A refusal emitted no artifact | Empty stdout, absent proposal path, unchanged configuration document digest **and** `mtimeNs`, unchanged legacy tree; `TC-MIG-003`, `TC-MIG-010`. |
| A watch read wrote nothing | The snapshot plus a recording write seam at zero calls, with no cache or timer registration; `TC-WFRESH-008`. |
| A report or preview wrote nothing | A full snapshot of the declared roots and a directory-creation count of zero; `TC-SIM-001`, `TC-MIG-014`. |

A snapshot is a sorted array of `relative-path|size|mtimeNs|mode|sha256` lines, so a content-preserving rewrite that changes mtime or mode still fails. `mtimeNs` is read with `statSync(path, { bigint: true }).mtimeNs`; a platform that cannot supply nanosecond precision is a declared gap in §10, never a silent downgrade to seconds.

### 4.4 Invariant rules for permanent suites

- **No permanent suite asserts a diff against a moving base branch.** No case reads `origin/main-tools...HEAD`, no case asserts an exactly-changed-file set, and no case asserts a changeset count. Branch-shape ideas become tree invariants: the declared counts, the closed sets, the page set, the help inventory and the fixture inventory.
- **Pinned counts that are delivered contracts are asserted exactly and by name.** The provider rows (16), the table (167), the documented rows (166), the arithmetic (`+133`), the allowlist (66), the vocabulary members (6 / 8 / 9 / 13), the evidence fields (14 / 17), the watch set (6) and the family count (26) are equality assertions.
- **Snapshots and goldens that pin preserved data move deliberately.** The only baselines this change touches are `tests/fixtures/provider/contract-inventory.json`, `tests/fixtures/help-guide/coverage.json`, `tests/structure/inventory.json`, the result-code corpora and the provider goldens; each is edited as a declared delta, never regenerated by blanket rewrite.
- **A rule without a failing fixture is a gap.** Every new guard ships its mutant in the same change (§4.3); a guard whose control is deferred is recorded in §8, not counted as covered.
- **Assert the value's meaning, not a growing count.** Where a population is expected to grow (legacy files per source directory, declared budgets, zone step-table entries), the assertion is a relation, not a magic total.
- **A guard that cannot fail is a vacuity, not a pass.** `VAC-TP-1` is recorded rather than presented as evidence.

### 6.3 Gate battery (numbered) and evidence shape

Every command runs from the repository root with the scratch temp directory, in this order.

```bash
# 1. Aggregate gate (the single quality gate)
TMPDIR=$PWD/tmp/tmpdir pnpm check

# 2. Narrow re-run of the changed-tier suites (for iteration and for the evidence count)
TMPDIR=$PWD/tmp/tmpdir bun test 'tests/behaviour/provider-*.test.ts' 'tests/structure/provider-*.test.ts' 'tests/checks/provider-*.test.ts' 'tests/golden/provider-*.test.ts' 'tests/behaviour/peak-pause-*.test.ts' 'tests/behaviour/peak-window-*.test.ts' 'tests/behaviour/daemon-peak-window-*.test.ts'

# 3. Boundary suite including the fixture-coverage meta-check
TMPDIR=$PWD/tmp/tmpdir bun test tests/boundaries

# 4. The CI error-table gate, run locally with the same script CI runs (deliberately not in pnpm check)
TMPDIR=$PWD/tmp/tmpdir bun run scripts/checks/error-table-sync.ts

# 5. Documentation conformance and the help/reference inventory
TMPDIR=$PWD/tmp/tmpdir bun test tests/checks/doc-conformance.test.ts tests/checks/help-guide-coverage.test.ts tests/checks/reference-page-parity.test.ts

# 6. Supplementary range gate (pre-PR commit-message check)
TMPDIR=$PWD/tmp/tmpdir ./scripts/lint-commit-range.sh --base main-tools
```

Evidence record (pm-notes `notes:` entry; `type` is a free-form string validated only for presence alongside `text`, so `evidence` is schema-valid; use `info` if a future lint narrows the vocabulary):

```yaml
- text: >-
    quality_gates evidence: gates 1-6 PASS —
    pnpm check (all tests, 0 fail); narrow provider tier (pass count / total);
    boundaries (pass count, fixture-coverage meta-check green);
    error-table-sync PASS (167 entries, 166 documented, 66 two-segment identities, 16 provider rows,
    BASELINE_ROWS.length + 133, 84 corpus rows); doc-conformance/help/reference PASS;
    lint-commit-range PASS; commit = the change-branch head the gates ran against; verdict PASS
  type: evidence
  date: "2026-11-19"   # the run date
```

Rules for the record: one entry per gate that moved a verdict; a `FAIL` names the failing suite and the remediation mode; an unresolved `ERROR` is recorded as `ERROR` and never rounded to `PASS`; the counts are stated as exact numbers; the commit is the change-branch head the gates ran against.

## 8. Risks, Assumptions, and Open Questions

### 8.1 Risks

| ID | Risk to this plan | Mitigation |
|---|---|---|
| TR-1 | The DST matrix is asserted against expectations computed in the test, so a shared bug between test and implementation would pass | The expected instants are derived from the declared rule in plain arithmetic (`local end`, offset delta, transition instant) and cross-checked against the delivered `peakWindowOpenSeconds`/`peakWindowEndSeconds` for the no-transition cell; the negative control resolves the offset once and must fail, so the matrix is proven to discriminate |
| TR-2 | The boundary-equality case degrades to three calls of one function and proves nothing about the watcher | The watcher driver is the delivered lane decision over parsed profile rules; the structural half asserts the functions' import sites; a UTC-only helper must fail the comparator |
| TR-3 | The one-read assertion passes because the fixture declares one budget | The count is asserted at 0, 1, 3 and 8 budgets, and the port records the scope list of its single call |
| TR-4 | `SPEND-TP-1` narrows because the spend payload exposes no per-observation instants | The ticket-scope arm is exact and unaffected; the window arm narrows to the fold-level oracle and the narrowing is recorded in §10 rather than papered over (`OQ-TP-2`) |
| TR-5 | The credential canary scan passes because it scans nothing | The scanner is driven over a planted canary and must fire (`TC-MIG-005`), and a non-credential name with the same value must still appear, so blanket redaction fails |
