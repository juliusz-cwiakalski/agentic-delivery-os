## Delivery-blocking risks

- **The headline claim has no production path** (finding 1). Until the agent source is decided, Phase 4 will implement a binding that no shipped invocation supplies, every real dispatch will disclose `unresolved-seat`, and the DoD's mandatory live observation will have nothing to run against. This is a scope/acceptance decision, not a wording fix: the human owner must choose between adding an agent input (scope growth, with its own AC/TC/phase) and narrowing the ticket claim (with the record and DoD updated to say so).
- **Phase 2 cannot be committed green as scoped** (finding 4). The bidirectional contract-surface inventory will be red the moment the new identities land, and the file is undeclared and ungated — the third iteration of the same class (iteration 1: state payload; iteration 2: attribution seam; iteration 3: the contracts export inventory).
- **Two identities for one observation, and none for its absence** (finding 2). Persisting `observedModel` beside the delivered `model` duplicates a schema axis under an unchanged identity, and the real store's 23 null agents / 487 null models still have no declared representation.
- **Attribution scope is undefined across attempts** (finding 3). The change narrows a delivered work-item-scoped behaviour (and the compaction checkpoint's content) to "the run" without saying which run a work-item-scoped closeout means.

## Verdict Rationale

The iteration-2 remediation is real and mostly lands. The seat rule is now stated once and is internally consistent across the spec, the test plan, the plan and TDR-0032's amendments; TC-011 asserts an invocation shape the installed single-valued CLI can accept; the attribution seam is declared end to end with its goldens, latency suite and composition; M1/M2/M3 are gone and the DoD gained two machine checks. Independently re-verified ground truth — the wrapper, `run --help`, the two store generations, the version distribution, the null agents/models, the index availability, the contract export inventory, the dispatch pre-flight seams — supports those claims.

What blocks delivery is a premise none of the three artifacts states. The whole propagation design is written as if a production dispatch names an agent; it does not. `HarnessSpawnInput` has no agent, `spawnArgs` has no `--agent`, the dispatch command has no flag, and the delivery scripts that do name an agent bypass the port entirely. The change therefore ships a contract that only a test double can exercise, which is exactly the defect class the gate caught in iterations 1 and 2 — now at the level of the ticket's headline acceptance criterion and the DoD's mandatory live evidence. Two further blockers are of the same family the gate has already failed twice: a bidirectional contract-surface fixture that Phase 2 must edit but does not declare, and a schema shape that duplicates the delivered observed-model identity while leaving the observed absence unexpressed. The attribution seam also moves a work-item-scoped behaviour to "the run" without saying which attempt that is.

Delivery must not start. Reopen `specification` for findings 1, 3, 5 and 9 (and for the acceptance/scope decision finding 1 raises, which pauses for the human owner), then `test_planning` for finding 6 and TC-043's two-attempt variant once finding 3 is settled, then `delivery_planning` for findings 2, 4, 7, 8 and 10. A fourth iteration should confirm three things: a shipped invocation can name an agent and the DoD's live step can be executed against it; Phase 2 declares and gates every file its contract surface touches; and the telemetry row states each fact exactly once.
