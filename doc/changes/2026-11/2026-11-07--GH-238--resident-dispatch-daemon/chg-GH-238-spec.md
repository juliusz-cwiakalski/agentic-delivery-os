# CHANGE SPECIFICATION

> **PURPOSE**: Make the delivery queue run continuously under a resident, single-instance, crash-safe daemon that supervises lanes through the delivered harness seam, keeps every fact in the state layer, converges after any kill or host restart without duplicating tickets, comments, or commits, applies preemption only at safe boundaries, never fires a merge, and degrades to fully functional CLI one-shots whenever it is absent.

## 1. SUMMARY

Deliver the resident dispatch daemon for M1. The daemon starts, stops, reports status, installs an optional user-level supervisor unit, acquires a fence-style single-instance lock with evidenced stale takeover, serves a local control socket whose wire contract is control protocol v1, drives the delivered scheduling engine continuously, spawns and observes lanes through an injected lane-executor seam over the delivered harness session port, records execution state and heartbeats through the state layer, reconciles every in-flight lane on start into `alive`, `interrupted`, or `crashed`, resumes from the phase ledger with delivered restart budgets, and converts a computed preemption into a safe-boundary park without ever killing a live session.

The change also delivers the external-effect protocol behind the crash-safety claims: `CommandReceipt` and `OutboxEffect` additive record kinds plus a domain primitive with first-class `unknown`, query-based check-before-reapply, and commit protection through a pre-commit outbox intent carrying a message-independent identity (baseline HEAD, change ref, phase, and the sorted normalized staged path set) matched on recovery by one bounded `logSince(baselineHead)` read, on top of the delivered atomic record-plus-commit primitive. It supersedes GH-237's temporary `--watch` refusal by accepting `queue --watch` and `lanes --watch` with bounded subscribe frames when the daemon is reachable and declared bounded state polling when it is not. It delivers no new tracker or VCS write path, no `dispatch` command, no dual-run evidence, and no per-repo handover; those remain M1-S9 / GH-239.

## 2. CONTEXT

### 2.1 Current State Snapshot

The one-shot scheduling engine is delivered (M1-S17 / GH-237): one folded queue graph, artifact-computed readiness on the delivered six-condition model, per-repository `repo-exclusive` leases acquired through the state layer's fence with evidenced stale takeover, release and park in one fenced transaction, weight classes as a per-runner resource class, producer-before-consumer batching with a producer-bound deploy gate, close-first ranking, parks with per-type recheck, a durable `clear-observed` marker, recovery incidents, the classified stuck-park finding, the `queue` and `lanes` command families, and truthful `degraded: ["daemon-unreachable"]` one-shot payloads. Its spec records two honest boundaries that this change closes: no production composition root wires the queue yet, and `--watch` is refused with a hint naming this story.

The state layer is delivered (M0-S5 / M1-S2): an append-only verified ledger under `delivery.state.v1`, additive record kinds without schema-version bumps, single-writer fence tokens with an explicit staleness window, verified reads, a disposable derived index, atomically replaced derived documents, and classified torn/unknown/permission failures. The result contract is delivered: one `CommandResult` envelope, the machine error table with a `{0, 1, 2}` exit projection, `fallback` containment, and a serialization redaction chokepoint. The configuration layer is delivered: typed branches with defaults and provenance, exact-key validation, and `config.value.invalid`. The typed `lane` branch already carries `lane.liveness-interval` and `lane.restart-budget`; the typed `queue` branch carries lease TTL and park recheck.

Session lifecycle economics is delivered (M1-S15 / GH-235): adapter-sourced progress signals, the prefill-safe liveness rule, `economics.restart` and `economics.budget-exhaustion` records, one admission gate shared by supervised-style and one-shot-style resume, and the terminal budget-exhaustion record. Typed blockers are delivered (M1-S16): append-only `blocker.question` and `blocker.answer` records with `applied: false` and a recorded `laneResume` projection; the applying actors were explicitly deferred to this story, coordinator supervision, and the one-shot resume path. Harness adapters are delivered (M1-S11): `HarnessSessionPort` exposes spawn, deliver, resume, collect, classify, liveness, and session listing over opencode and Claude Code with explicit capability gaps. Merge and verify deploy are delivered (M1-S4), and the commit primitive is delivered (M1-S14).

No resident daemon, control socket, NDJSON wire protocol, daemon install/uninstall, startup reconciliation, automatic preemption execution, external-effect primitive, or live watch stream exists. `daemon` is a planned registry entry with no delivered command, and the delivered `queue` and `lanes` contracts still refuse `--watch`. The status digest still reports its `lanes-or-queue` section as a declared capability gap. Every command is one-shot by construction.

### 2.2 Pain Points / Gaps

- Lanes idle between coordinator iterations: the queue computes the next action, but nothing claims and supervises it without an operator or agent invocation.
- A resident process has no safe ownership story: no lock, no takeover rule, no evidence that two daemons cannot both drive one state directory.
- Crash recovery is undocumented machinery: no reconciliation classifies an in-flight lane, no restart budget is applied by a supervisor, and no artifact-based rule prevents duplicate tickets, comments, or commits.
- Computed preemption has no executor: GH-237 emits a preemption action, but the release is manual and nothing applies it at a safe boundary.
- External effects have no crash-safe protocol: a tracker transition, comment, or commit that lands before its receipt has no first-class `unknown` state and no check-before-reapply rule.
- Commands have no wake-now or live notification path: a queue mutation takes effect only at the next one-shot read, and `--watch` is refused rather than delivered.
- A resident process has no polling discipline: nothing prevents a daemon from hammering tracker or CI APIs.
- Supervision has no install path: no user-level unit, no login start, no scoping to the state directory, and no declared outcome on platforms without the adapter.
- The state-mediated truth principle has no operational proof: no command has a control-socket optimization, so "socket never the only route" cannot be tested.

## 3. PROBLEM STATEMENT

Because the delivery loop has a one-shot scheduler but no resident driver, every lane start still depends on a coordinator or agent invocation; there is no single-instance owner, no crash-safe reconciliation, no safe-boundary preemption execution, no first-class external-effect receipt protocol, no live watch, and no declared polling discipline for a process that runs continuously — so idle lanes wait, a killed daemon can lose or duplicate work, a computed preemption can strand a close item, a resident process can overload provider APIs, and the system's state-mediated truth claim remains untested.

## 4. GOALS

- **G-1**: A resident daemon that drives the delivered queue continuously, claims and releases leases through the delivered scheduler, and records every execution fact in the state layer.
- **G-2**: Single-instance ownership per state directory, enforced by a fence-style lock with an explicit staleness bound, evidenced stale takeover, and a refused live competitor.
- **G-3**: State-mediated truth with the control socket as an optimization: every command interaction completes through state alone, every wake is optional, and no fact that matters lives only in memory.
- **G-4**: Control protocol v1 as a layered NDJSON contract — codec, session, transport — with `n`/`n-1` negotiation, bounded buffers, closed interaction classes, no business truth on the wire, no secrets, and a reserved caller-principal field.
- **G-5**: A transport-independent protocol proven over stdio, with the unix socket as the local default and remote or container-attached transports left as additive configuration seams.
- **G-6**: Crash-safe startup reconciliation that classifies every in-flight lane from artifact evidence, resumes `interrupted` and `crashed` lanes from the ledger, skips completed phases idempotently, and enforces the delivered restart budget durably.
- **G-7**: A lane supervision seam that proves the daemon spawns and observes through the delivered `HarnessSessionPort` and never becomes a lane or runs delivery work in-process.
- **G-8**: An external-effect protocol with `OutboxEffect` intent, `CommandReceipt` outcome, first-class `unknown`, query-based check-before-reapply, and commit protection through a message-independent pre-commit outbox identity (baseline HEAD, change ref, phase, staged path set) matched by one bounded `logSince(baselineHead)` read over the delivered atomic record-plus-commit primitive.
- **G-9**: Automatic preemption execution that never kills a live session and applies only at a safe phase boundary or on session completion.
- **G-10**: Truthful degradation: daemon failure or absence leaves every CLI one-shot fully functional, and status and watch declare the degradation instead of failing silently or idling.
- **G-11**: Bounded live watch for `queue` and `lanes`, superseding GH-237's refusal while preserving its truthfulness requirement.
- **G-12**: Resident polling hygiene: per-platform tracker and CI rate limits and exponential backoff as configuration.
- **G-13**: An optional, scoped supervisor installation with a concrete Linux adapter and explicitly classified unsupported outcomes on platforms without one.
- **G-14**: Guarded vocabulary growth — additive record kinds, an exact `daemon` error-row set, typed `daemon` and `poll.<platform>` configuration branches, and a changeset — synchronized in-change.
- **G-15**: Structural proof that the daemon never fires a merge: no merge code path, an asserted absence, and a status field that says so.

### 5.1 Capability Details

- **F-1**: `daemon` gains `start [--foreground]`, `stop [--mode drain|immediate]`, `status [--live]`, `install`, and `uninstall`. `start` resolves the state-directory scope as the brand-derived `<PREFIX>_STATE_DIR` environment variable when the process environment sets it and otherwise as the default `<home>/<brand.stateDirectoryName>`; there is no `--state-dir` flag and no state-directory configuration key (DEC-18, Appendix E). `start` acquires the single-instance lock, runs startup reconciliation, opens the control transport, begins the heartbeat, and returns once the daemon is ready to serve; `--foreground` keeps the process attached, while the default returns after readiness and leaves the daemon resident. `stop` defaults to `drain`: it refuses new spawn decisions, lets in-flight lane bookkeeping reach a boundary, leaves live lane sessions running and recorded as detached, releases the lock, and exits; `immediate` stops the control loop and exits without signalling any lane. `stop` is state-first and never requires the socket: when the control transport is reachable it uses the control frame, otherwise it signals the recorded process and does not append a false release; the daemon appends its own release record when it exits, and an unclean exit leaves a stale lock for the next start to take over. Against an absent daemon, `stop` is an explicit idempotent `noop` at exit 0. `status` reads state and reports instance identity, uptime, queue depth, lane states, restart counters with classified reasons, heartbeat age, socket reachability and transport, supervisor state, and `mergeCodePath` from the closed set `{"absent", "present"}` (the production composition always computes `"absent"`); `status --live` asks the socket for immediate facts and fails closed with a classified identity when the socket or heartbeat is unavailable. `install` and `uninstall` manage an optional user-level supervisor unit scoped to the state directory; the unit exports the resolved scope through `Environment=<PREFIX>_STATE_DIR=<canonical absolute state directory>`. Every outcome uses the delivered `CommandResult` envelope, with `data` on success and the classified error on failure; human mode prints a deterministic summary before any detail. The exit projection is: `0` for a running daemon, a successful stop/drain/noop, an installed or removed unit, and a plain status that truthfully declares degradation; `1` for a second instance against a live lock, a refused takeover, an unsupported protocol version, and an invocation rejection; `2` for an unreachable live query, a failed state recovery, an unavailable supervisor adapter, and an unreadable state.
- **F-2**: The single-instance lock is a daemon-owned lock artifact in the state directory, acquired by exclusive creation, carrying a unique lock token and the same staleness discipline as the state fence, but it is **not** the state layer's single-writer fence: the state fence is held only for the short duration of each append and is never held for the daemon's lifetime. The lock token is a same-user ownership capability, never a credential: it is permitted only in the three control-frame payloads (`drain`, `stop`, `takeover`) and in durable lock and instance records, and it carries no credential-shaped value. Exactly one live instance may hold the daemon lock per state directory. A second `start` while the lock is live refuses `daemon.already-running` at exit 1, naming the instance identity, process identity, acquisition time, heartbeat time, and heartbeat age, and appends nothing. A lock whose heartbeat age is at or beyond `daemon.lock-staleness` is stale and takeover-eligible: the new instance acquires the lock, appends an instance record whose operation is `taken-over`, and carries previous instance, previous lock token, last heartbeat time, heartbeat age, and takeover time as evidence. A live lock is never taken over: an explicit `takeover` control action or state request against a live lock appends nothing and refuses `daemon.takeover-refused` at exit 1, while a `daemon start` against that same live lock refuses `daemon.already-running`. The state fence's own staleness window is a separate mechanism used only to protect one write; it is never conflated with the daemon lock bound. A different state directory is a different store and a different lock, so multiple projects on one host run independent daemons without contention.
- **F-3**: State is the only shared truth and the only durable route. Commands write intent records to the state layer — queue entries, priorities, dependency edges, blocker answers, resume notes — and optionally poke the control socket for wake-now behavior. The daemon writes execution records — leases, lane execution state, heartbeats, parks, restart decisions, preemption state, and the redrive detection receipt — and the external-effect primitive writes outbox and receipt records, all under the same fence discipline. Every command interaction has a state-only fallback: `queue add`, `queue prioritize`, `queue dep`, `queue claim`, `queue release`, `blockers answer`, `blockers publish`, `phase complete`, and `commit` all land without a daemon. Every CLI intent record carries its record identity as the idempotency key — the immutable store-scoped identity for the delivered queue, dependency, and blocker kinds, and the declared `idempotencyKey` for effect intents; the client supplies the intent, not a separate key. An identical replay under one key appends no second intent record. The daemon applies queue intents on its next wake or on start. A blocker answer is durable and visible as soon as it lands with its recorded `laneResume` projection; on its next wake or on start the daemon records the pending resume/application intent on the lane's execution record when a lane exists, without altering the delivered `applied: false` answer record, and actual lane application happens at the next safe phase boundary when a lane exists; full session resume remains M1-S9. The daemon wakes in a declared order: a control-socket `poke`, its own tail-follow of the state event log, then a bounded poll interval. Losing a poke, a tail notification, or a poll tick changes nothing durable because the next wake re-reads state. No command requires a socket, and no frame carries a fact that cannot be re-derived from state.
- **F-4**: Control protocol v1 is newline-delimited JSON. Every v1 frame carries `v` (protocol major version), `id` (correlation, absent on unsolicited events), `kind` (one of `request`, `response`, `event`, `error`), `type`, and `callerPrincipal`; a v0 frame is the v1 shape without the additive reserved fields and is accepted only where its fields are sufficient. A request carries `payload`; a response carries `data`; an error carries the delivered error-object field set. The daemon serves version `1` and the declared compatibility floor `0`; a version outside that set is refused with an error frame carrying `daemon.protocol.unsupported` and the offered versions `[1, 0]`, and the connection closes. Version `0` is that compatibility shape; a v0 frame that omits a field its own version requires is refused through the delivered error table. Interaction classes are closed: `poke` (a state-changed notification carrying an event cursor, answered with `applied`), `query` (immediate facts such as daemon status, lane state, or queue depth, answered with a response labeled `live`), `subscribe` (a request accepted with a response followed by bounded `event` frames on the closed topics `queue` and `lanes`), and `control` (`drain`, `stop`, and `takeover`, each requiring the daemon lock token — the fence-style ownership token — and each also expressible without the socket through a signal or a state record). Each subscription has a bounded buffer; on overflow the daemon emits one `event` frame of type `degraded` carrying `subscriber-overflow`, drops the subscription, and never blocks the dispatcher. No business truth crosses the wire: every frame is derivable from state or is an at-most-once control action, and losing any frame leaves the system correct. No credential value, credential token, secret material, prompt, body, transcript, diff, or provider payload transits: a credential fact is a variable name only. The daemon lock token is the one exempt same-user ownership capability, never a credential; it appears only in the `drain`, `stop`, and `takeover` payloads and in durable lock and instance records, and it carries no credential-shaped value. A `callerPrincipal` field is present on every v1 frame as `{ kind: "local-same-user", id: string | null }`; a v0 frame omits it. It is unauthenticated, never used for authorization in M1, and reserved so a later lane-scoped authorization can retrofit without a schema break.
- **F-5**: The protocol is three layers. The codec encodes and decodes frames and owns the error vocabulary; it knows nothing about sockets, files, or processes. The session layer owns connection lifecycle, request/response correlation within one connection, subscriptions, bounded buffers, timeouts, and version negotiation; it talks in frames, not bytes. The transport layer is any ordered byte stream selected by configuration: `unix` is the local default, `stdio` is implemented and used by the conformance suite, and `tcp`, `tls`, `ssh`, and container-pipe values are declared but not delivered. The unix socket lives inside the `0700` state directory, same-user only, with the socket file at `0600`, and a cross-user connection is refused with the delivered `state.permission.denied` at exit 1, naming the socket path and the same-user requirement. `daemon.transport` and `daemon.socket-path` select the transport and endpoint; a socket path outside the state directory is refused with the delivered `config.value.invalid` at exit 1, and a transport value that is declared but not delivered is refused with `config.value.invalid` naming the implemented set rather than silently falling back. A transport that cannot open at start leaves the daemon in declared transport-degraded mode with `daemon-socket-unreachable`; state-mediated operation continues and the socket is never reported reachable. The same frames and the same session logic run over stdio, which is the transport-independence proof: no codec or session behavior may depend on transport identity. Remote and container-attached transports later reuse the same frames and add exactly one additive `intent` frame class and a handshake identity claim; neither is delivered here, and the protocol shape reserves their place instead of rewriting it.
- **F-6**: Every CLI invocation opens its own connection. Responses are routed only to the connection that asked; the `id` field correlates requests and responses within one connection, never across connections. The daemon is a multi-connection, single-event-loop server: accepted frames from all connections are processed on the loop, shared in-memory state is mutated only on the loop, and slow or idle connections never block it because each connection and subscription has a bounded buffer. At-most-once mutation is a state-path property, not a wire-frame property. Control protocol v1 has no mutating wire class: the only mutating frames are the control-plane `drain`, `stop`, and `takeover`, which carry no business intent and are at-most-once by connection identity plus frame `id` plus the daemon lock token, and each of them is also expressible without the socket. Business mutations (`queue add`, `queue prioritize`, `queue dep`, `queue claim`, `queue release`, `blockers publish`, `blockers answer`, `phase complete`, and `commit`) are CLI intent records written through the single-writer state fence; each carries its record identity as the idempotency key, and an identical replay under one key appends no second intent record and leaves exactly one effective intent. A `queue add` therefore has no relayed wire form and no external effect: it is a state append whose identical replay is a state no-op. The additive `intent` frame class that would carry a business mutation over the wire is explicitly deferred to M4-S6 and is not part of M1. Every request has a bounded response timeout; on timeout, unreachable transport, or refused version the CLI degrades to its state-path fallback or declared degraded mode instead of blocking the agent. Cross-connection leakage, one invocation receiving another's response, a duplicate effective application for one idempotency key, and a control frame applied twice for one (connection, `id`, lock token) key are contract violations, not retryable behavior.
- **F-7**: The daemon writes a durable heartbeat record every `daemon.heartbeat-interval`, carrying instance identity, a monotonically increasing beat ordinal, the beat time, uptime, queue depth, lane counts, the current spawn identity when one exists, and the event-log cursor it has consumed. `daemon status` reads the latest heartbeat and reports one of three states: `running` when the heartbeat age is below `daemon.lock-staleness` and the instance record has not released the lock, `stale` when the age is at or beyond `daemon.lock-staleness`, and `stopped` when the instance record says the daemon released the lock. The heartbeat is liveness evidence for humans and agents; it is not an authorization claim. A stale or absent heartbeat makes a plain status declare `degraded` at exit 0 and makes `status --live` fail with the classified identity at exit 2. The heartbeat record never carries a prompt, message body, transcript, diff, credential, or absolute repository root.
- **F-8**: On start the daemon performs one bounded, idempotent reconciliation. It rebuilds the queue graph, lanes, leases, parks, and restart budgets from verified state. For every lane whose last recorded state is delivering or detached, it gathers artifact evidence: the recorded operating-system process identity, the harness session identity and whether the session is observable, the phase ledger's last completed phase, and the presence or absence of a failure record. It then classifies the lane exactly once: `alive` when the session or process is observable — reattach and observe, no restart increment; `interrupted` when the process and session are gone with no failure record (host restart, kill, supervisor stop) — resume from the ledger position, skip already-completed phases idempotently, and consume exactly one restart through the delivered restart-budget gate; `crashed` when a failure record exists — classify the recorded reason and resume per budget. A lane at or past `lane.restart-budget` becomes a terminal `failed` lane projection, and its queue entry is held terminal with `restart-budget-exhausted`; the lane carries the delivered `economics.budget-exhaustion` record and the restart history, and raises a typed question within one `daemon.heartbeat-cycle` with the delivered exhaustion options; exhaustion never silently requeues. The reconciliation appends one `daemon.reconciliation` record carrying the queue counts, per-lane classification and action, restart decisions, duplicate count (which must be zero), and any question identities, and it is bounded by `daemon.reconcile-max-lanes`. A replay of the same classification appends no duplicate decision and increments no restart twice. When evidence is insufficient to choose among the three classes, the lane is held with the explicit `evidence-insufficient` reason and re-evaluated on the next pass; it is never guessed into a class and never silently resumed. Unreadable state refuses the start with `daemon.state-recovery-failed` at exit 2, leaves every one-shot path available, and never starts half-reconciled. Reconciliation also detects each unresolved effect and records a durable redrive request — for a commit, the discovered SHA after the bounded `logSince(baselineHead)` read, or `unknown` — without creating a commit, appending a phase transition, or re-applying (F-9, F-10, DEC-19).
- **F-9**: The daemon is a supervisor, never a lane. It computes the next action with the delivered scheduling engine, claims the lease through the delivered fenced claim path, and asks an injected lane-executor port to start the lane. The delivered lane-executor adapter composes the delivered `HarnessSessionPort` for spawn, observe, collect, and liveness; the full typed delivery loop, prompt selection, dual-run evidence, per-repo handover, and key=value delivery summary remain M1-S9. The daemon process contains no delivery work: it does not read repository code, run a phase, write a commit, or evaluate a gate. The effect owner is the lane or one-shot process that owns the phase completion: it applies and re-applies an effect and restores a commit binding by re-running phase completion with the detected commit as evidence; the daemon's effect duty stops at detection, one bounded query, and the durable redrive request (DEC-19, TDR-0014 INV-7). It records lane execution state through `daemon.lane` records — ref, daemon execution state (`delivering`, `detached`, `completed`, `failed`, `preempted`), harness kind and session identity, recorded process identity, ledger position, spawn ordinals, liveness outcome, and classification — and releases or parks the lease when the lane terminates or is preempted. The daemon execution state is distinct from the delivered six-value `lanes` projection; the projection folds daemon evidence without redefining its vocabulary. If no lane-executor is composed, the daemon runs in a declared `supervise-only` mode: it reconciles, serves status and control, computes and publishes the next action, and reports `degraded: ["lane-executor-unavailable"]`; it never pretends to have spawned a lane. Progress-based liveness consumes the delivered harness and economics signals at `lane.liveness-interval`: a corroborated stall follows the delivered `watchdog.liveness-stalled` classification and restart admission, and a prefilling or resuming session with rising token delta or traffic is never classified stalled.
- **F-10**: Every externally visible effect is written as an intent first and an outcome second. An `OutboxEffect` record carries an effect identity, the originating intent identity, the work-item ref, a closed effect kind (`tracker-transition`, `tracker-comment`, `commit`), the bounded target identity, a payload digest rather than payload content, an idempotency key, an optional `callerPrincipal`, and its state; for `effectKind: commit` it also carries the baseline HEAD, the change ref, the phase, and the sorted normalized staged path set the wrapper is about to stage; it carries no message, subject, body, or message fingerprint (TDR-0014 INV-1..INV-3). The bounded effect content is resolved from the durable originating intent at apply time, so the outbox record never stores free-form message content. A `CommandReceipt` record carries the effect identity, attempt ordinal, query verdict, receipt status (`applied`, `already-applied`, `failed`, `unknown`), bounded evidence, and the time. The effect state machine is `accepted` → `in-flight` → `applied` or `failed` or `unknown`. `unknown` is first-class and means the effect may have landed before its receipt. Before any re-apply of an `unknown` effect, the protocol performs one bounded query by stable identity and applies check-before-reapply. For a tracker transition or comment the query is the comment identity or the transition identity; a negative query permits one re-apply, a positive query records `applied` and appends no second effect, and an unreadable query leaves the effect `unknown` and forbids a blind retry. For a commit the query is one bounded `CommitGitPort.logSince(baselineHead)` read, and the verdict is `applied` only when the read yields exactly one commit after the baseline **and** that commit's normalized changed-path set equals the recorded set; zero commits, more than one commit, a path-set mismatch, or an unreadable or over-cap read leaves the effect `unknown` with no automatic re-apply and no guessed SHA. Commit effects are ordered so the outbox intent is durable before the commit primitive is invoked: the commit-effect wrapper appends the intent, then calls the delivered atomic record-plus-commit primitive unchanged. On restart or re-drive, the owning process's bounded `logSince(baselineHead)` read detects a commit that landed after the intent but before its transition record and telemetry; a match records the landed SHA as `applied` and creates no second commit, and any ambiguous outcome stays `unknown`. The daemon detects and records a durable redrive request and never applies; the lane or one-shot owner restores the binding (F-9, DEC-19, TDR-0014 INV-7..INV-8). The commit message composition, the commit format, and the atomic record-plus-commit primitive are not changed; the only additive surface is one bounded read on the git port. The protocol is proven against injected external-effect adapters; no tracker or VCS write adapter operation ships in this change. The commit convergence test carries three negative controls — one that breaks the recorded path-set derivation, one that removes the log query, and one that breaks the path-set match rule — and each must make the test fail.
- **F-11**: When the delivered scheduler computes a preemption for a close item, the daemon applies it only at a safe boundary and never kills a live session. If the preempted lane has no active session, the daemon releases the lease and records the named park `preempted-for-close-item` with condition type `preemption` immediately, and records the applied preemption with the close item named. If the preempted lane has an active session, the daemon records a pending preemption, lets the session reach its next phase boundary or complete, and only then releases the lease and records the park; the pending state is durable, survives a daemon restart, and is re-evaluated during reconciliation. Single-flight holds until the release lands, so the close item is not scheduled in the same pass. The explicit `queue release --park preempted-for-close-item` path remains valid and performs the same fenced release-and-park; the daemon is not a second implementation of the release semantics.
- **F-12**: The daemon is optional and never authoritative. If it is absent, stopped, unreachable, or crashed, every CLI command completes through the state path: queue mutations land, blockers answers land, `phase complete` and `commit` are unaffected, and queue/lanes reads compute from state with `degraded: ["daemon-unreachable"]` at exit 0. When the daemon is reachable, that marker is absent, so the degradation is a fact, not a constant. A command that times out on the socket falls back to state and reports the degradation instead of failing. `daemon status` without a daemon is an explicit stopped or stale report at exit 0, not a failure and not an idle hang; `status --live` is the only surface that fails closed. A daemon that cannot recover state refuses to start and names one-shot guidance, leaving the stack usable. The daemon's absence never changes a one-shot result, a lease decision, a park decision, or a blocker answer.
- **F-13**: `queue --watch` and `lanes --watch` are accepted. With a reachable daemon, the invocation subscribes to the closed `queue` or `lanes` topic, prints an initial bounded snapshot, then prints one bounded event frame per line until interrupted; frames are deduplicated, carry their finding codes, and never exceed the frame bound. With no reachable daemon, the invocation enters a declared degraded mode, polls state at `daemon.watch-poll-interval`, prints a degraded marker naming `daemon-unreachable`, prints only changed bounded snapshots, and exits 0 when interrupted; it never fails and never emits a silent empty stream. If state itself is unreadable, the invocation exits 2 with the delivered classified `state.*` identity instead of polling a lie. Mid-stream subscriber overflow drops that subscription to the same bounded polling with a `subscriber-overflow` degraded marker; the dispatcher is unaffected. This supersedes GH-237's temporary refusal while preserving its truthfulness requirement: an absent daemon is declared, never hidden.
- **F-14**: The resident process polls tracker and CI only through the delivered read seams and only within per-platform policy. Each platform declares a base interval, a maximum interval, and a minimum request spacing; failures back off exponentially from the base to the maximum, and a success resets to the base. The policy is configuration (`poll.<platform>.base-interval`, `poll.<platform>.max-interval`, `poll.<platform>.min-spacing`), validated with the existing configuration identities. Polling never bypasses a delivered adapter, never performs a write, and never exceeds the configured rate. A one-shot command is not subject to the resident backoff state and reads once.
- **F-15**: `daemon install` registers an optional user-level supervisor unit scoped to the state directory so the daemon starts at login and survives logout. On Linux the concrete adapter writes a systemd user unit with `ExecStart=<binary> daemon start --foreground`, `Type=simple`, and `Restart=on-failure`, whose state-directory scope is bound explicitly in the unit through `Environment=<PREFIX>_STATE_DIR=<canonical absolute state directory>` rather than inherited from an ambient working directory or selected by a CLI flag, and enables linger; install is idempotent and reports the unit identity and linger state. The foreground entry keeps the supervised process attached and resident, while the default `daemon start` remains the interactive spawn-and-return form; the unit's argument vector is written as data and is never shell-evaluated. A failed linger enablement removes the unit it just wrote and returns `daemon.supervisor-unsupported` with the platform evidence, so a partial install is never reported as success. On platforms without a delivered adapter — launchd on macOS and the Windows service equivalent — `install` returns the classified `daemon.supervisor-unsupported` at exit 2 naming the platform and the missing adapter; it never exits 0 silently and never pretends to have installed anything. `uninstall` removes only what the adapter created, disables linger only when this installation enabled it, and is an idempotent `noop` when nothing is installed. Installation is optional: with no unit, every one-shot command works identically, and the daemon simply is not resident. The unit carries no secret, no ambient working directory assumption, and no shell-evaluated content; its only scope binding is the `Environment=` entry.
- **F-16**: Vocabulary growth lands in-change: seven additive record kinds inside `delivery.state.v1` with their own payload schemas and store-scoped keys; one new `daemon` error kind with exactly eight documented rows; one typed `daemon` configuration branch and one typed `poll` branch; the additive optional `callerPrincipal` field on the existing and new intent record kinds; an additive `watch` interaction on the queue and lanes surfaces; and one changeset entry. The delivered `queue` and `lanes` payloads, the six readiness conditions, the lease and park vocabularies, the weight and rank classes, the lane-state set, the economics records, and the collector-id set are unchanged. No new status collector id is introduced: daemon state is projected through the delivered `lanes` collector and the `daemon status` payload. The machine error table, the documented table, the source references, the fixtures, and the changeset agree in both directions.
- **F-17**: The daemon contains no merge code path. It may read merge readiness, rank a merge-ready entry, and prepare it for the coordinator, but it cannot invoke the merge transaction, evaluate a merge gate, or land a change. The absence is structural — a dependency-boundary rule whose `from` set covers the core daemon paths, the CLI daemon paths, and the adapters daemon subpath (`^packages/core/src/(app|domain)/daemon`, `^packages/cli/src/daemon`, `^packages/adapters/src/daemon/`) forbids importing merge execution; a source-level import of merge from any daemon path therefore fails the boundary. Separately, a reachability test asserts that no merge invocation is reachable from the daemon composition: injecting a merge executor makes the composition compute `mergeCodePath: "present"` but adds no import edge, so the injection proof and the import proof are distinct. `daemon status` reports `mergeCodePath` from the closed set `{"absent", "present"}`, computed by the composition rather than from prose: the production composition always computes `"absent"`, and `"present"` appears only when a merge executor is injected in a test composition. A future change that adds merge execution to the daemon would fail the boundary and the assertion.

## 6. USER & SYSTEM FLOWS

```
Flow 1: Start a resident daemon
  Operator or login unit → daemon start
    → resolve state-directory scope (`<PREFIX>_STATE_DIR` when set,
      else `<home>/<brand.stateDirectoryName>`); acquire the daemon lock token
    · live lock held by another instance → daemon.already-running, exit 1,
      evidence: instance, pid, acquiredAt, heartbeat age; 0 appends
    · stale lock (heartbeat age ≥ daemon.lock-staleness) → takeover,
      append daemon.instance operation=taken-over with previous evidence
    → rebuild queue, lanes, leases, parks, budgets from verified state
    → classify each in-flight lane alive / interrupted / crashed
    → append daemon.reconciliation; begin heartbeat; open the control socket
    → envelope: instance, reconciliation, socket, heartbeat, degraded[]
    → exit 0.  A one-shot stack never depends on this succeeding.

Flow 2: Second instance and stale takeover
  daemon start (second invocation)
    → lock is live → daemon.already-running at exit 1, naming the holder
  daemon start (after kill -9, lock stale)
    → takeover: daemon lock acquired; daemon.instance operation=taken-over
      carries previous instance, previous lock token, last heartbeat, heartbeat age
    → reconciliation resumes the world; 0 duplicated effects

Flow 3: Kill mid-delivery and restart
  kill -9 <daemon pid>; daemon start
    → instance record says the previous process did not release the lock
    → for each delivering/detached lane:
      · session/process observable → alive, reattach, no restart
      · gone with no failure record → interrupted, resume from ledger,
        skip completed phases, restart +1 through the delivered gate
      · failure record present → crashed, classify reason, resume per budget
    → past budget → terminal failed lane + terminal queue hold
      + economics exhaustion + typed question within one collection cycle;
      never silent requeue
    → commits: outbox intent (baseline HEAD, change ref, phase, staged
      path set) + one bounded logSince path-set match + delivered atomic
      record-plus-commit; the owning lane/one-shot process restores the
      transition binding, the daemon only records the redrive request;
      zero/multiple/mismatch/unreadable stays unknown, no automatic re-apply;
      tracker/comment effects: receipt + unknown-first-class +
      check-before-reapply
    → 0 duplicated tickets, comments, or commits

Flow 4: Commands while the daemon is down
  queue add GH-401 --priority 5
    → intent lands under the fence; no socket involved
    → envelope degraded=["daemon-unreachable"]; exit 0
  blockers answer q-8f21 --choice 2
    → answer and resume note land; applied=false; exit 0
  daemon start (later)
    → reconciliation makes each queue intent effective once; each answer
      stays durable and visible, the resume/application intent is recorded
      in the lane record, and a lane-holding answer applies at the next
      safe phase boundary (full session resume remains M1-S9)

Flow 5: Poke, tail, and bounded poll
  command writes intent → optional poke frame {cursor}
    → daemon re-reads state and returns applied
  poke lost or socket absent → daemon tail-follows the event log
  tail unavailable → bounded poll at daemon.poll-interval
    → any lost wake is recovered by the next read; nothing durable is lost

Flow 6: Query and subscribe
  daemon status --live → query on its own connection → response {live:true}
  lanes --watch → subscribe topic=lanes → response {ok:true}
    → initial bounded snapshot; then event frames, one JSON object per line
    → slow subscriber buffer overflows → event type=degraded
      {reason:"subscriber-overflow"} → drop to bounded state polling
    → dispatcher loop latency unchanged

Flow 7: Watch without a daemon
  queue --watch (daemon down)
    → declared degraded mode: "daemon unreachable; polling state"
    → bounded snapshots at daemon.watch-poll-interval, changes only
    → interrupt → exit 0; no failure, no silent empty stream
  state unreadable → exit 2 with the classified state.* identity

Flow 8: Automatic preemption at a safe boundary
  scheduler emits preemption: GH-310 merge-ready, GH-311 holds repo-alpha
    → GH-311 has no active session → release lease + park
      preempted-for-close-item immediately; preemption applied
    → GH-311 has an active session → record pending preemption; never kill
      → next phase boundary or session completion → release + park
      → preemption record carries boundary evidence and names GH-310
    → single-flight holds until release; GH-310 schedules next pass

Flow 9: External effect with unknown consequence
  outbox effect accepted → in-flight → transport dies before receipt
    → effect state = unknown
    → query by stable identity (comment id / transition id / commit
      path-set identity via one bounded logSince(baselineHead))
      · found → command.receipt applied; no second effect
      · not found → re-apply allowed, one attempt, new receipt
      · query unreadable → stays unknown; no blind retry
    → commit path: outbox intent + delivered atomic record+commit
      → exactly one new commit whose changed-path set equals the
        recorded set → applied with the landed SHA, no second commit
      → zero, multiple, mismatch, or unreadable → unknown; no automatic
        re-apply; the owning lane/one-shot process decides and restores
        the phase binding from the detected SHA

Flow 10: Install and uninstall
  daemon install (Linux)
    → systemd user unit: ExecStart=<binary> daemon start --foreground,
      Type=simple, Restart=on-failure,
      Environment=<PREFIX>_STATE_DIR=<canonical state dir>; linger enabled
    → envelope: supervisor=systemd-user, unit, linger=true, scope; exit 0
  daemon install (macOS / Windows)
    → daemon.supervisor-unsupported at exit 2 naming platform and adapter
    → no file written, no silent no-op
  daemon uninstall
    → removes only what this install created; idempotent noop otherwise
    → one-shot operation unchanged with or without the unit
```

## 7. SCOPE & BOUNDARIES

### 7.1 In Scope

- The `daemon start|stop|status|install|uninstall` command family with deterministic human output, machine envelopes, and the `{0, 1, 2}` exit projection (F-1).
- Fence-style daemon lock ownership, stale-lock takeover with evidence, and per-state-dir isolation (F-2).
- State-mediated truth with an optional control socket, declared wake sources, and a state-only fallback for every interaction (F-3).
- Control protocol v1: NDJSON frames, request/response/event/error kinds, poke/query/subscribe/control classes, `n`/`n-1` negotiation, bounded buffers, overflow degradation, no business truth, no secrets, reserved caller principal (F-4, C-2).
- Codec/session/transport layering, config-selected transport, unix socket default, stdio conformance, and additive remote seam (F-5).
- Connection-per-invocation concurrency, single event loop, id correlation, state-path at-most-once intent application, control-frame at-most-once by (connection identity, `id`, lock token), bounded timeouts, and graceful fallback (F-6).
- Durable heartbeat and status projection (F-7).
- Startup reconciliation, alive/interrupted/crashed classification, ledger resume, restart accounting, budget enforcement, terminal failure, and typed questions (F-8).
- Lane supervision through an injected lane-executor port over `HarnessSessionPort`, with the daemon never a lane and never executing delivery work in-process (F-9, C-1).
- External-effect protocol records and primitive: `OutboxEffect`, `CommandReceipt`, `unknown`, check-before-reapply, and commit protection through a message-independent pre-commit outbox identity matched by one bounded `logSince(baselineHead)` read over the delivered atomic commit (F-10, DEC-15).
- Safe-boundary automatic preemption with durable pending state and no live-session kill (F-11).
- Daemon-down continuity, degraded status, and one-shot equivalence (F-12).
- `queue --watch` and `lanes --watch` with bounded subscribe frames and declared bounded polling without a daemon (F-13, C-4).
- Per-platform polling rate limits and exponential backoff as configuration (F-14).
- Optional scoped supervisor installation with the Linux systemd adapter using the pinned foreground unit that sets `<PREFIX>_STATE_DIR`, and classified unsupported outcomes elsewhere (F-15, DEC-18).
- Additive record kinds, the `daemon` error-row set, `daemon` and `poll` configuration branches, the reserved caller-principal field, and the changeset (F-16, C-2).
- Structural proof that no merge code path exists in the daemon (F-17).

### 7.2 Out of Scope

- [OUT] `dispatch`, the full typed delivery loop, prompt selection, dual-run evidence, per-repo handover, and the key=value delivery summary (M1-S9 / GH-239).
- [OUT] Tracker, VCS, or CI writes. The external-effect primitive is delivered; no production write adapter is added.
- [OUT] Merge execution, gate evaluation, waiver handling, rebase-refresh, and landing. The daemon only prepares and queues.
- [OUT] Remote, TCP, TLS, SSH, and container-attached transports; the additive `intent` frame class; and the handshake identity claim (M4-S6).
- [OUT] Multi-host, fleet, or distributed lock coordination.
- [OUT] `status --watch`; the digest watch remains that surface's own reconciliation.
- [OUT] Tracker-driven queue discovery and automatic queue membership.
- [OUT] Lane-scoped authorization, credential sidecars, and containerized lanes; the caller principal is reserved, unauthenticated policy only.
- [OUT] Changes to `queue ready`, the six readiness conditions, lease/park semantics, weight or rank classes, lane-state vocabulary, or the delivered queue and lanes payloads beyond additive `--watch` and the reserved field.
- [OUT] Status digest `lanes-or-queue` behaviour and its declared gap.
- [OUT] Automatic merge preparation beyond the delivered merge-ready ranking; no new merge queue record.

### 7.3 Deferred / Maybe-Later

- The production lane executor and full dispatch loop once M1-S9 lands; the injected port and `daemon.lane` records are the seam.
- The launchd and Windows supervisor adapters; the classified unsupported outcome is the current contract.
- Remote and container-attached control with the additive `intent` frame class and handshake identity (M4-S6).
- Lane-scoped authorization using the reserved caller principal once a credential sidecar or container boundary exists.
- A `status --watch` stream over the same protocol.
- Additional subscription topics (for example provider parks or typed questions) beyond `queue` and `lanes`.
- Adaptive polling policy beyond the per-platform base/cap/spacing configuration.
- Daemon-side merge preparation records once the coordinator's merge transaction exposes a prepared state.

## 8. INTERFACES & INTEGRATION CONTRACTS

### 8.1 REST / HTTP Endpoints

None. The daemon exposes no HTTP surface and no network listener by default. Its interfaces are the `daemon` command grammar and envelope (Appendix C), the local control protocol frames (Appendix B), the additive state record kinds (Appendix D), the `daemon` error identities (Appendix F), and the typed configuration branches (Appendix E). All provider traffic remains the delivered read-only tracker, pull-request, check-run, and deploy-trace reads; the external-effect protocol uses injected adapters and adds no production write operation.

New record kinds join the existing state schema additively: no schema-version bump, no migration, no backfill, and no change to existing record kinds, reads, boundaries, or the state ledger format. The additive optional `callerPrincipal` field on intent records is backward-compatible: a record without it reads exactly as before. No record or frame carries a secret, a credential value, a credential token, a prompt, a message body, a transcript, a diff, or a free-form provider payload; the daemon lock token is the sole exempt same-user ownership capability and appears only in control-frame payloads and durable lock/instance records.

### 8.4 External Integrations

- **State layer** — the only durable substrate; all daemon, lane, preemption, receipt, and outbox records append through the fenced port with verified reads.
- **Scheduling engine** — consumed for readiness, precedence, claim, release, park, weight, and preemption computation; no parallel scheduling implementation is introduced.
- **Harness adapters** — `HarnessSessionPort` is composed by the lane-executor adapter for spawn, observe, collect, classify, and liveness; no harness is called directly by the daemon core.
- **Session lifecycle economics** — the restart-budget admission gate, `economics.restart`, and `economics.budget-exhaustion` are consumed; the daemon does not invent a second counter.
- **Typed blockers** — the daemon reads recorded answers and resume projections, keeps the answer durable and visible, records the pending resume/application intent on the lane execution record when a lane exists without mutating the delivered `applied: false` answer, and applies at the next safe phase boundary when a lane exists; full session resume remains M1-S9, and the blocker channel remains the only question/answer writer.
- **Merge and verify deploy** — read-only readiness and landing facts; the daemon never invokes the merge transaction.
- **Commit primitive** — the only production external-effect adapter; the commit-effect wrapper appends an `outbox.effect` intent (baseline HEAD, change ref, phase, sorted normalized staged path set) before invoking the delivered atomic record-plus-commit primitive, which is unchanged. The kill-after-commit-before-record window is detected on restart by the outbox intent plus the bounded path-set read, not by an adapter that grants the property.
- **Phase-completion evidence contract** — the owning lane or one-shot process restores a detected commit binding by re-running phase completion with the redrive request's discovered SHA as commit evidence, through the delivered `commit-without-record` convergence row, so the phase converges to `both` and never to `record-only`; the daemon never runs a phase and never appends a transition (DEC-19, TDR-0014 INV-8). The delivery plan declares the exact files this contract touches.
- **Git port (additive read)** — the additive `CommitGitPort.logSince(baselineHead)` read returns the bounded, ordered commits after the baseline with each commit's SHA and normalized changed-path set (repo-relative paths, `/` separators, deduplicated, sorted, and a deterministic rename representation that contributes the delete and add paths). A message is never read, matched, or recorded. The read is additive over the existing git seam; it changes neither M1-S14's commit format nor its atomic record-plus-commit primitive.
- **Provider engine** — read-only provider availability and park facts; no provider write.
- **Systemd user manager, launchd, Windows service manager** — supervisor adapters, invoked only by `daemon install`/`uninstall`; the Linux unit pins `ExecStart=<binary> daemon start --foreground`, `Type=simple`, `Restart=on-failure`, and the explicit `Environment=<PREFIX>_STATE_DIR=<canonical state directory>` scope binding, while absent or unsupported platforms produce a classified outcome.
- **Tracker and CI read APIs** — read-only through delivered seams, subject to the configured per-platform rate limits and backoff. No tracker or VCS write is added.

### 8.5 Backward Compatibility

- **One-shot behavior is unchanged.** `queue ready`, `queue list|plan|add|prioritize|dep|claim|release`, and `lanes list|show` keep their grammars, payload shapes, exit projections, and state-only semantics. The daemon adds a wake optimization, never a dependency.
- **`--watch` changes truthfully.** GH-237 refused `--watch` with a remediation hint. This change accepts it: with a daemon it streams bounded frames; without one it declares degraded bounded polling at exit 0. The refusal is superseded explicitly, and the truthfulness requirement is preserved because an absent daemon is always named.
- **State is additive.** Seven record kinds join `delivery.state.v1` with no schema-version bump. A store that has never seen a daemon record reads as verified-empty, never torn. The optional `callerPrincipal` field is backward-compatible; old records read unchanged.
- **Error table growth is additive.** A new `daemon` domain kind with eight rows joins the delivered table. No existing row is renumbered, removed, or reinterpreted. The collector-id set is unchanged.
- **Configuration growth is additive.** New `daemon` and `poll` branches ship with defaults, so an absent branch is valid and every existing command behaves identically without operator action.
- **The daemon is optional.** A project that never runs `daemon start` or `daemon install` sees no behavior change beyond the now-accepted `--watch` flags and the additive reserved field.
- **The status digest is not rewired.** Its `lanes-or-queue` section keeps its declared gap; the daemon does not claim or edit it.

## 10. TELEMETRY & OBSERVABILITY REQUIREMENTS

- **Heartbeat is the liveness surface.** `daemon status` reads the durable heartbeat and reports running, stale, or stopped with the age; no operator has to infer liveness from a process listing.
- **Reconciliation is the durable start report.** Every start appends one `daemon.reconciliation` record with queue counts, per-lane classification, restart decisions, duplicate count, and question identities. The same facts are rendered in the `daemon start` envelope and human output.
- **Lane records are the execution evidence.** `daemon.lane` records carry the daemon execution state, session identity, process identity, ledger position, and liveness outcome; the delivered `lanes` view consumes the same execution evidence rather than inventing a second lane-state vocabulary.
- **Effects and receipts are the crash-safety audit trail.** `outbox.effect` and `command.receipt` records make every external effect inspectable: what was intended, what was attempted, what the query found, and whether it landed; a detected commit lands a durable redrive request naming the discovered SHA or `unknown`, so an operator can act without reading process memory.
- **Pending preemption is observable.** A durable `daemon.preemption` record in `pending` state is visible in status; an applied preemption names the boundary and the close item.
- **Degradation is declared, never implied.** Every daemon surface carries `degraded[]` with a closed marker; a stopped daemon, a stale heartbeat, an unreachable socket, a missing executor, and a subscriber overflow each produce a named marker rather than a silent empty or zero view.
- **Error identities are shared.** Control-frame errors use the same machine error table as CLI errors, so a client can branch on `code`, `category`, `retryable`, and `consequence` without a second vocabulary.
- **No new exporter or background collector.** The change adds no metric exporter, trace span, log sink, or alert channel. The command audit ledger continues to capture every CLI invocation automatically; the daemon's own operations are represented by its durable records.

## 12. ASSUMPTIONS

- One state directory is one project scope and one single-writer store; multiple projects on one host use separate state directories and separate daemons.
- The filesystem boundary is the only local authorization: every same-user process, including a lane session executing repository code, is inside it. This is accepted for M1; the escape paths are the parked credential-sidecar and containerized-lane concepts.
- The delivered `HarnessSessionPort` is available and can report liveness for a spawned session; a harness that declares a gap returns the declared gap rather than an invented signal.
- The delivered restart-budget gate and economics records are the only restart counter; the daemon does not add a second counter.
- The delivered scheduling engine owns readiness, precedence, claim, release, park, and preemption computation; the daemon consumes it rather than reimplementing it.
- The full typed delivery loop, prompt selection, dual-run evidence, per-repo handover, and key=value summary arrive with M1-S9; until then the lane-executor port is injected and the production daemon can run in declared supervise-only mode.
- The Linux target has a systemd user manager and can enable linger; launchd and Windows service adapters are declared but not delivered.
- Tracker and CI reads remain read-only through delivered seams; no write adapter is added by this change.
- External-effect adapters are injected for tracker transitions and comments; the commit primitive is the only production effect adapter.
- The existing git adapter can answer one bounded read for commits after a baseline HEAD, returning each commit's SHA and normalized changed-path set; the commit message is not deterministic on the production path and is never part of an effect identity.
- The wrapper can compute the staged path set before the commit with the delivered pure staging computation over a tree read and the same scope request the primitive receives, and the working tree is not concurrently modified between that read and the primitive's read.
- `<PREFIX>_STATE_DIR` is the only state-directory scope selector: no `--state-dir` flag and no state-directory configuration key exists, and an unset variable resolves to `<home>/<brand.stateDirectoryName>`.
- The daemon does not need to survive a machine power loss with stronger guarantees than the state layer's append-only ledger and atomic derived-document replace provide.
- A queue entry maps to at most one supervised lane at a time; the delivered single-flight lease is the enforcement.
- No fleet, multi-host, or remote-worker coordination exists in M1.

## 18. ROLLOUT & CHANGE MANAGEMENT (HIGH-LEVEL)

- **Delivery order**: vocabulary and configuration first (record declarations, `daemon` and `poll` branches, error rows); then the codec/session protocol proven over stdio; then the unix transport, single-instance lock, heartbeat, and lifecycle commands; then reconciliation and lane supervision; then the external-effect protocol; then preemption; then watch and degradation; then the supervisor adapter; then documentation reconciliation. Each step is independently testable and independently revertible.
- **Additive cutover**: no delivered command changes behavior except the additive `--watch` acceptance and the additive reserved field. The state schema keeps its version, the error table only grows, the collector-id set is unchanged, and configuration ships with defaults so an absent branch is valid.
- **Opt-in residency**: the daemon is optional. A project that never starts or installs it keeps the delivered one-shot behavior; `queue` and `lanes` reads report `degraded: ["daemon-unreachable"]` exactly as before.
- **Fail-safe default**: if reconciliation cannot read state, the daemon refuses to start with a classified identity and leaves one-shots available. It never starts half-reconciled.
- **Kill switch**: `daemon stop --mode immediate` and `daemon uninstall` are always available; neither signals a live lane, and the next start reconciles what remains.
- **Supervisor posture**: install is optional and scoped. The Linux unit runs the foreground entry under `Type=simple` with `Restart=on-failure`; an installed unit is the only thing that makes the daemon start at login, and its absence or removal changes nothing for one-shot operation.
- **Communication**: the daemon man page, command registry, glossary, architecture overview, new resident-daemon feature spec, and the affected current-truth specs land in the same change. The status digest's `lanes-or-queue` gap is flagged to its owner rather than edited here.

## 19. DATA MIGRATION / SEEDING (IF APPLICABLE)

None. Seven additive record kinds join `delivery.state.v1` with no schema-version bump, no migration, no backfill, and no rebuild command. The additive optional `callerPrincipal` field on intent records is backward-compatible: a historical record without it reads exactly as before, and no record is rewritten. A store that has never seen a daemon record reads as verified-empty, so an existing installation starts with no daemon state and a one-shot stack that is fully functional. The delivered queue graph and economics folds continue to rebuild from their own verified records; the daemon adds no derived document and no seed data. Configuration branches ship defaults, and the effect, frame, classification, and degradation vocabularies are contract data.

## 20. PRIVACY / COMPLIANCE REVIEW

No personal data is introduced. Records and frames carry instance and process identities, state-directory scope identifiers, work-item refs, lane and session identities, restart ordinals and classified reasons, effect identities and payload digests, bounded typed evidence, and timestamps. A `callerPrincipal` value is a local label (`local-same-user` with an optional opaque id), not a person's identity, and it is never authenticated. No prompt text, message body, transcript, diff, file content, credential value, or raw provider payload appears in any record, frame, report, golden, log line, or telemetry event.

The socket path is rendered by local `daemon start` and `daemon status` envelopes and human output, and by a deterministic golden only as the declared placeholder `<state-dir>/daemon.sock`; it is never persisted un-normalized to a state record, a golden, a log line, or a telemetry event. The durable instance record stores a state-directory scope identifier, not an absolute path: the scope is a SHA-256 digest (first 16 lowercase hex characters) of the canonical absolute state-directory path, the path-to-scope mapping is recoverable by recomputing the digest for a candidate directory, and the digest is one-way. The daemon never records an absolute repository root; the delivered queue entry's internal root remains the only such value and is never rendered by a daemon surface. The change performs no tracker or VCS write, so it neither reads nor transmits anything a delivered read path does not already expose, and the delivered redaction chokepoint covers every new payload.

## 21. SECURITY REVIEW HIGHLIGHTS

- **The filesystem boundary is the authorization model.** The unix socket lives in the `0700` state directory, the socket file is `0600`, and a cross-user connection is refused with the delivered `state.permission.denied` at exit 1. Every same-user process — including a lane session executing repository code — is inside that boundary and could in principle write intent records, send control frames, or read state. This residual risk is accepted for M1; the escape paths are the parked credential-sidecar and containerized-lane concepts.
- **Per-state-dir scoping isolates projects, not lanes from the engine.** Two projects on one host cannot see each other's records or frames, but a lane in the same project is inside the trust boundary. The spec states this explicitly instead of implying lane isolation.
- **The caller principal is not authorization.** It is an additive, unauthenticated reserved field on intent records and a required field on v1 frames (omitted on v0). No access decision reads it. It exists so a later lane-scoped authorization can retrofit without a schema break.
- **No business truth and no secrets on the wire.** Every frame is derivable from state or is an at-most-once control action. Credential facts are variable names only; no credential value, credential token, secret material, prompt, body, transcript, diff, or provider payload transits. The daemon lock token is a same-user ownership capability, never a credential; it is permitted only in the `drain`, `stop`, and `takeover` payloads and in durable lock/instance records, never in a `daemon start`, `daemon stop`, or `daemon status` command envelope or golden, and it carries no credential-shaped value. A lost or observed frame cannot change a durable outcome.
- **Control frames are bounded and validated.** A frame over `daemon.frame-max-bytes` is refused before parsing into an action; unknown kinds, types, versions, and closed-vocabulary values are refused through the delivered error table; malformed frames cannot reach a state mutation.
- **Subscriber isolation is a denial-of-service control.** Per-connection and per-subscription buffers are bounded; overflow drops the subscriber, never the dispatcher. A hostile or slow same-user client cannot stall delivery.
- **No shell and no ambient execution.** The supervisor adapter writes a unit as data; it does not shell-evaluate the unit or its argument vector, and the unit binds the state-directory scope explicitly through `Environment=<PREFIX>_STATE_DIR` rather than through an ambient working directory. The daemon spawns only through the injected lane-executor and harness port, with the delivered deny-by-default environment descriptor.
- **Merge absence is a source-level invariant, not a runtime one.** The dependency-boundary rule's `from` set covers the core daemon paths, the CLI daemon paths, and the adapters daemon subpath, so an import of merge execution fails the check; the injected-executor `mergeCodePath: "present"` proof is a reachability assertion and is deliberately distinct from the import proof.
- **External effects are at-most-once by construction.** Intent, receipt, first-class `unknown`, query-based check-before-reapply, and, for commits, a message-independent pre-commit outbox identity matched by one bounded `logSince(baselineHead)` read prevent a retry from duplicating a tracker transition, comment, or commit; an ambiguous commit outcome is `unknown` with no automatic re-apply, and only the owning lane/one-shot process restores the binding.
- **Preemption never signals a live session.** The only preemption action is a fenced lease release plus a named park at a safe boundary; there is no kill path and no signal path.
- **Truthful degradation is a security property.** A stale heartbeat, an unreachable socket, an unreadable store, an exhausted subscriber, and an unsupported supervisor each produce a declared classified outcome; none produces a silent all-clear, a zero view, or an empty stream.

## 22. MAINTENANCE & OPERATIONS IMPACT

- **Vocabulary is guarded.** Frame kinds, interaction classes, topics, effect kinds, effect states, receipt statuses, instance operations, lane classifications, degradation markers, error codes, and configuration keys are closed sets (NFR-14); growth requires a spec change and, where cross-cutting, a decision record.
- **Tuning is configuration.** Heartbeat cadence, lock staleness, poll and wake intervals, response timeout, watch poll interval, subscription buffer, frame bound, and per-platform polling policy are configuration (NFR-10). Changing them requires no code change.
- **The daemon is optional.** If it is not installed or not running, the stack is a one-shot stack. Operating the daemon means `daemon start`, `daemon status`, and optionally `daemon install`; stopping it means `daemon stop` or `daemon uninstall`.
- **Reconciliation is the recovery runbook.** After a host restart, a kill, or a supervisor stop, `daemon start` appends a reconciliation report that names every in-flight lane and every restart decision. An operator diagnoses from that report and the heartbeat, not from process grep.
- **Effect forensics** are the `outbox.effect` and `command.receipt` records: intent, attempts, query verdict, and terminal status. A stuck `unknown` is visible and is resolved by a query, never by a blind retry, and a detected commit is a durable redrive request that the owning lane/one-shot process applies — the daemon never does.
- **Scope selection is environment-only.** `<PREFIX>_STATE_DIR` selects the state directory, the supervisor unit sets it through `Environment=`, and an unset variable resolves to `<home>/<brand.stateDirectoryName>`; there is no flag and no configuration key to keep in sync.
- **Polling posture** is per platform and configurable; a resident process never hammers an API, and a one-shot command keeps its single read.
- **Doc duties land in-change**: the new resident-daemon feature spec, the state-layer, configuration, result-contract, scheduling-engine, economics, blockers, harness-adapter, and commit-primitive updates, the command registry, the man page, the glossary, the architecture overview, `doc/00-index.md`, and the changeset.
- **Known follow-ups are named, not assumed away**: the production lane executor and full dispatch loop (M1-S9), the launchd and Windows adapters, remote transport (M4-S6), `status --watch`, lane-scoped authorization, and the full blocker-resume execution (M1-S9; the M1 applied semantics are pinned in OQ-5/DEC-16).

| Query | An immediate-fact request answered with a response labeled `live`, derivable from state. |
| Subscribe | A request accepted with a response followed by bounded `event` frames on a closed topic. |
| Bounded subscriber | A subscription with a fixed buffer; on overflow it is dropped to declared state polling and the dispatcher is unaffected. |
| Codec / session / transport | The three protocol layers: frame encoding and errors; connection lifecycle, correlation, subscriptions, buffers, and timeouts; the ordered byte stream selected by configuration. |
| Transport independence | The property that the same frames and session logic run over stdio and the unix socket, proven by the conformance suite. |
| Caller principal | The reserved, unauthenticated `{ kind: "local-same-user", id }` field on v1 frames (omitted on v0) and optionally on intent records; never authorization. |

| Alive | An in-flight lane whose process or session is observable; reattach and observe, no restart increment. |
| Interrupted | An in-flight lane whose process and session are gone with no failure record; resume from the ledger, skip completed phases, consume one restart. |
| Crashed | An in-flight lane with a recorded failure; classify the reason and resume per budget. |
| Restart budget | The delivered `lane.restart-budget` bound consumed through the delivered admission gate; exhaustion is terminal, loud, and never a silent requeue. |

| Supervise-only | The declared daemon mode when no lane executor is composed: reconcile, serve status and control, publish the next action, spawn nothing, and report the degradation. |

| Pending preemption | A durable preemption intent awaiting a safe boundary; survives a daemon restart. |
| External-effect protocol | Intent (`OutboxEffect`), outcome (`CommandReceipt`), first-class `unknown`, query-based check-before-reapply, and, for commits, a message-independent pre-commit identity plus one bounded `logSince(baselineHead)` path-set read over the delivered atomic commit (TDR-0014 INV-1..INV-8). |

| Effect owner | The lane or one-shot process that owns the phase completion and therefore applies, re-applies, and restores the binding; the daemon only detects, queries, and records a redrive request (DEC-19). |

| Unknown consequence | The first-class state in which an effect may have landed before its receipt; it forbids a blind retry and requires a query. |
| Check-before-reapply | A bounded query by stable identity before re-applying an `unknown` effect. |
| Safe boundary | A phase boundary or session completion at which a lease can be released and a park recorded without killing live work. |

| Supervisor unit | The optional user-level unit scoped to the state directory that starts the daemon at login and survives logout; Linux uses a systemd user unit with linger. |
| Merge absence | The structural property that no daemon path can execute, evaluate, or invoke a merge; asserted by boundary, reachability test, and status. |

Frame envelope: `{ v, id?, kind, type, callerPrincipal, payload? | data? | error? }`. `v` is `1` or the compatibility floor `0`; a v1 frame carries `callerPrincipal`, and a v0 frame omits it and is accepted only where its fields are sufficient. `id` is present on a request, its response, and its error; absent on unsolicited events. A frame larger than `daemon.frame-max-bytes` is refused before action. The only mutating frames are `drain`, `stop`, and `takeover`; each is also expressible without the socket (signal or state). The `lockToken` in those three payloads is the daemon's same-user ownership capability, never a credential; it carries no credential-shaped value and appears nowhere else on the wire.

Payload field sets are closed and validated at the ledger boundary:

- `daemon.instance` — `schema`, `instanceId`, `pid`, `scope` (the DM-1 digest identifier, never a path), `lockToken`, `operation` (`acquired`, `taken-over`, `released`, `immediate-stop`), `acquiredAt`, `heartbeatAt`, `releaseReason?`, `takeover?` (`previousInstanceId`, `previousLockToken`, `lastHeartbeatAt`, `heartbeatAgeMs`, `takenOverAt`), `recordedAt`.
- `daemon.heartbeat` — `schema`, `instanceId`, `ordinal`, `beatAt`, `uptimeMs`, `queueDepth`, `laneCounts` (`delivering`, `idle`, `parked`, `failed`), `currentSpawn?` (`ref`, `sessionId`), `cursor`, `recordedAt`.
- `daemon.lane` — `schema`, `ref`, `state` (`delivering`, `detached`, `completed`, `failed`, `preempted`), `harnessKind?`, `sessionId?`, `processId?`, `ledgerPosition?` (`lastCompletedPhase`), `spawnOrdinal`, `liveness?` (`classification`, `observedAt`), `detachedAt?`, `classification?` (`alive`, `interrupted`, `crashed`), `resumeIntent?` (`questionId`, `mode` from the delivered `laneResume` closed set), `recordedAt`. A `resumeIntent` transition is the boundary-application observable for a blocker answer, together with exactly one executor resume/attach call for that answer and zero when no lane exists; the answer record itself stays `applied: false`.
- `daemon.reconciliation` — `schema`, `instanceId`, `queue` (`entries`, `edges`, `parks`), `lanes[]` (`ref`, `classification?`, `action`, `restarts`, `reason?`), `duplicates`, `questions[]`, `startedAt`, `completedAt`, `truncated`, `recordedAt`.
- `daemon.preemption` — `schema`, `ref`, `repository`, `closeRef`, `parkCause` (`preempted-for-close-item`), `conditionType` (`preemption`), `holder`, `state` (`pending`, `applied`, `withdrawn`), `requestedAt`, `appliedAt?`, `boundary?` (`phase`, `observedAt`), `evidence[]`, `recordedAt`.
- `command.receipt` — `schema`, `effectId`, `attempt`, `queryVerdict` (`found`, `not-found`, `unreadable`), `status` (`applied`, `already-applied`, `failed`, `unknown`), `evidence[]`, `recordedAt`.
- `outbox.effect` — `schema`, `effectId`, `intentId`, `ref`, `effectKind` (`tracker-transition`, `tracker-comment`, `commit`), `target`, `payloadDigest`, `idempotencyKey`, `callerPrincipal?` (the same optional/backward-compatible rule as every other intent kind), `state` (`accepted`, `in-flight`, `applied`, `failed`, `unknown`), `attempts`, `checkStrategy` (`query-by-id`, `query-by-log-since`), `baselineHead?`, `changeRef?`, `phase?`, `stagedPaths?` (sorted, normalized, repo-relative; only for `effectKind: commit`), `recordedAt`. The commit fields are present only for `effectKind: commit` and are absent for tracker kinds; the record never carries a message, subject, body, or message fingerprint. The bounded effect content is resolved from the durable `intentId` at apply time; this record stores no free-form content.
- `command.receipt` also carries the redrive detection shape for DM-18: effect identity, `attempt: 0`, queried baseline, `queryVerdict`, the discovered SHA when proven, and the time; a detection records no attempt ordinal in the effect's attempt count, does not advance the effect state machine, and never counts as an attempt.

The additive optional `callerPrincipal` field appears on the intent record kinds named in C-2 and on every new intent-kind record; it is absent on execution and outcome records. Every CLI intent record carries its record identity as the idempotency key — the client supplies the intent, not a separate key: the immutable store-scoped record identity for the delivered queue, dependency, and blocker kinds (an identical re-send resolves to the same key and appends no second intent record), and the declared `idempotencyKey` for effect intents. The control frame envelope carries no idempotency key; control application is keyed on (connection identity, `id`, lock token). Latest record per identity wins; an identical intent replay appends no second intent record. A wrong kind, malformed payload, duplicate acquisition for one instance, a second live instance record for one scope, or an illegal effect-state transition is a classified `state.*` failure, never a fabricated value. No schema-version bump, migration, or backfill exists.

#### Process environment — state-directory scope

The state-directory scope is a process-environment contract, not a configuration key and not a command flag:

| Variable | Shape | Default when unset | Semantics |
|---|---|---|---|
| `<PREFIX>_STATE_DIR` | absolute directory path | `<home>/<brand.stateDirectoryName>` | Selects the state directory every daemon path resolves: the lock artifact, the heartbeat and instance records, the control socket, and the scope digest. `<PREFIX>` is the brand-derived uppercase prefix, never a hardcoded product name. The supervisor unit sets it explicitly through `Environment=`; a value that is not an absolute path or that cannot be used as a state directory is `config.value.invalid` at exit 1. |

Precedence is exact: an explicitly set `<PREFIX>_STATE_DIR` wins over the default derivation; the two are never merged, and no ambient working directory participates. Two different values route to two independent locks, sockets, and stores, and a daemon started under one scope never attaches to another scope's lock or socket (DEC-18, AC-F15-1).

### Appendix F — Error identities

The new `daemon` domain kind carries exactly eight rows. Every row is documented and machine-declared together, names a reachable behaviour, and projects through the delivered `{0, 1, 2}` exit taxonomy.

| Code | Category | Retryable | Consequence | Projection | Triggers when |
|---|---|---|---|---|---|
| `daemon.already-running` | user | false | `not_landed` | user-validation (1) | A `daemon start` runs while a live instance holds the lock; the holder, instance identity, acquisition time, and heartbeat age are named; nothing is appended. |
| `daemon.takeover-refused` | transient | true | `not_landed` | user-validation (1) | An explicit `takeover` control action or state request targets a lock that is still live; no evidence of staleness exists; nothing is appended. A `daemon start` against that live lock instead refuses `daemon.already-running`. |
| `daemon.heartbeat-stale` | platform | true | `not_landed` | platform-provider (2) | `daemon status --live` reads a heartbeat age at or beyond `daemon.lock-staleness`; a plain status instead reports a degraded success at exit 0. |
| `daemon.state-recovery-failed` | platform | true | `not_landed` | platform-provider (2) | Startup reconciliation cannot read queue, lane, lease, park, or budget state; the daemon refuses to start half-reconciled and names one-shot guidance. |
| `daemon.protocol.unsupported` | user | false | `not_landed` | user-validation (1) | A control frame carries a version outside `{1, 0}`; the offered versions are named and the connection closes. |
| `daemon.socket-unreachable` | platform | true | `not_landed` | platform-provider (2) | `daemon status --live` cannot reach the configured transport; one-shot commands and a watch instead report `daemon-unreachable` as a degraded success at exit 0. |
| `daemon.subscriber-degraded` | transient | true | `not_landed` | platform-provider (2) | A subscribe request is refused because the daemon's subscription capacity is exhausted before any event; an established subscription that overflows instead emits a `degraded` event and falls back to polling at exit 0. |
| `daemon.supervisor-unsupported` | platform | false | `not_landed` | platform-provider (2) | `daemon install` runs on a platform without a delivered supervisor adapter (launchd, Windows service equivalent); the platform and missing adapter are named and no unit is written. |

An unreadable or torn daemon state reuses the delivered `state.*` identity at exit 2. A cross-user socket connection is refused with the delivered `state.permission.denied` at exit 1; a socket path outside the state directory reuses the delivered `config.value.invalid` at exit 1. Neither reuses a new `daemon` row, so the closed set remains exactly eight rows. A plain status over an absent or stale daemon is a success with a declared degradation marker, not a row. A watch over unreadable state exits 2 with the delivered `state.*` identity. An invocation rejection such as an unknown flag reuses the delivered `fallback.invocation` containment at exit 1. No `queue`, `lanes`, `blockers`, `economics`, `config`, or `state` row changes. The collector-id set remains `{tracker, lanes}`.

### Appendix H — Startup reconciliation algorithm

| Step | Rule | Outcome on failure |
|---:|---|---|
| 1 | Acquire or take over the daemon lock; append `daemon.instance` with operation `acquired` or `taken-over` | A start against a live lock is `daemon.already-running`; an explicit takeover against a live lock is `daemon.takeover-refused`; both exit 1 with 0 appends |
| 2 | Rebuild queue graph, lanes, leases, parks, and restart budgets from verified state | `daemon.state-recovery-failed`, exit 2; daemon does not start |
| 3 | For each lane in `delivering`/`detached`, gather artifact evidence: recorded process, harness session observability, last completed ledger phase, failure record | A missing evidence source is `unknown`, never a fabricated alive or crashed |
| 4 | Classify exactly once: `alive` (observable), `interrupted` (gone, no failure), `crashed` (failure recorded) | If evidence is insufficient, the lane is not classified in this pass; it is reported with reason `evidence-insufficient` and held for the next pass, never silently resumed |
| 5 | `alive` → reattach and observe; no restart increment | — |
| 6 | `interrupted` → resume from the ledger position; completed phases idempotently skipped; consume one restart through the delivered gate | Delivered `dispatch.restart-budget-exceeded` or `dispatch.resume-uneconomical` refusal; terminal failure per step 8 |
| 7 | `crashed` → classify the recorded reason; resume per budget | Same as step 6 |
| 8 | At or past `lane.restart-budget` → terminal `failed` lane projection, terminal queue hold with `restart-budget-exhausted`, delivered `economics.budget-exhaustion` record, typed question within one `daemon.heartbeat-cycle`; no silent requeue | Terminal append failure is surfaced as `terminalAppendError` on the refusal; the entry is not requeued |
| 9 | Append one `daemon.reconciliation` record with counts, per-lane classification, restart decisions, duplicate count (0), and question identities | A failed append fails the start with the classified state identity; the daemon does not claim a reconciled start |
| 10 | Begin heartbeat and open the transport | A failed transport open starts the daemon in declared transport-degraded mode with `daemon-socket-unreachable`; state-mediated operation continues and the socket is never reported reachable |

Steps 1–2 are prerequisites; steps 3–9 are bounded by `daemon.reconcile-max-lanes` and idempotent on replay; step 10 is the only step that can be retried after start without re-running reconciliation.

### Appendix I — External-effect state machine

| Current | Trigger | Next | Evidence |
|---|---|---|---|
| (none) | An effect intent is recorded | `accepted` | `outbox.effect` with identity, kind, target, payload digest, idempotency key; a commit also carries baseline HEAD, change ref, phase, and the sorted normalized staged path set |
| `accepted` | The effect is dispatched | `in-flight` | Attempt ordinal, start time |
| `in-flight` | A successful outcome is observed | `applied` | `command.receipt` `applied` |
| `in-flight` | A definite failure is observed | `failed` | `command.receipt` `failed` with bounded reason |
| `in-flight` | Transport dies, outcome unknown | `unknown` | `command.receipt` `unknown` |
| `unknown` | (tracker) Query by stable identity finds the effect | `applied` | `command.receipt` `already-applied`; no second effect |
| `unknown` | (commit) The single bounded `logSince(baselineHead)` read yields exactly one new commit whose normalized changed-path set equals the recorded set | `applied` | `command.receipt` `already-applied` with the landed SHA; no second commit |
| `unknown` | (tracker) Query finds nothing | `accepted` → `in-flight` | One re-apply attempt; new receipt |
| `unknown` | (commit) The read yields zero commits, more than one commit, a path-set mismatch, or is unreadable or over its cap | `unknown` | Durable redrive request (DM-18); no automatic re-apply and no guessed SHA; the owner decides |
| `unknown` | Query is unreadable (tracker) | `unknown` | No blind retry; remains visible |
| `applied` | Any duplicate drive | `applied` | `already-applied` receipt; no second effect |
| `failed` | A new attempt is authorized | `in-flight` | Attempt ordinal increments; the prior failure remains evidence |
| any | An illegal transition is attempted | unchanged | Classified `state.*` failure; no fabricated state |

Commit effects add one structural rule: the wrapper appends the `outbox.effect` intent (baseline HEAD, change ref, phase, sorted normalized staged path set) before invoking the delivered atomic record-plus-commit primitive, and any re-drive first performs the one bounded `logSince(baselineHead)` read; `applied` holds only for exactly one new commit whose normalized changed-path set equals the recorded set, and zero, multiple, mismatch, or unreadable resolves `unknown` with no automatic re-apply. The daemon detects and records the durable redrive request; only the owning lane/one-shot process applies the effect and restores the phase binding. The delivered commit message composition, commit format, and atomic record-plus-commit primitive are unchanged, and three negative controls — a broken path-set derivation, a removed log query, and a broken match rule — each make the convergence test fail. Tracker transitions and comments use `query-by-id`; commits use `query-by-log-since`.
