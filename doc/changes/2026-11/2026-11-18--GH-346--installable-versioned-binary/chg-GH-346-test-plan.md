# Test Plan - M4-S1: Installable, versioned binary — self-contained artifact and the composed install lifecycle

## 1. Scope and Objectives

This change turns an installed pointer into a product artifact and gives that artifact a lifecycle, so the risk is not a missing command — it is a change that *looks* delivered while one of its independent truths is false. Each truth is proven as a comparison a test runs, never as a prose claim. **First, the artifact stands alone.** One additive build entry emits one host-built executable whose identity is a compile-time constant; it answers `--version`, `--help`, and one composed read-only command (`phase list <ref> --json`, a delivered family, chosen because it exists in phase 1) from an empty directory with a scrubbed `PATH`, no `HOME` content and no checkout (3/3), a dirty-tracked-tree build reports `<commit>-dirty` and mutates no tracked file, two consecutive builds report the same identity and different bytes, and no output claims reproducibility (`TC-BIN-060`..`TC-BIN-063`). **Second, the identity is truthful inside a shape that must not move.** Four token situations render exactly one declared line (`TC-BIN-064`), no field is added and `--version --json` is byte-identical to `--version` (`TC-BIN-065`), and self-description stays read-free even with a recording `git` stub on `PATH` and a poisoned environment (`TC-BIN-066`, `TC-BIN-067`). **Third, the compiled process edge is correct.** The user argument slice is exactly the user arguments (`TC-BIN-068`), the re-entry path and the service unit name the real executable and never a `/$bunfs/root/` value (`TC-BIN-069`), and `--print-install-path` remains the resolver's authority (`TC-BIN-070`).

**Fourth, the lifecycle is a surface, not a script.** Five entry points resolve through both composed programs (`TC-INST-001`), each has its own static-inventory help (`TC-INST-002`), a missing runtime is a containment at exit `2` rather than an absent family (`TC-INST-003`), the alias refuses all five typedly and writes nothing (`TC-INST-004`), and grammar refusals plus the destination-not-an-input rule answer through the delivered `fallback.invocation` (`TC-INST-005`, `TC-INST-006`). **Fifth, the safety rules are admissions and orderings, not warnings.** A linked worktree is refused before anything is written (`TC-INST-010`), four admissible origins record the declared provenance (`TC-INST-011`), a dirty origin is admitted (`TC-INST-012`), a development run is refused (`TC-INST-013`), and the composition contains no network client and no build spawn (`TC-INST-014`).

**Sixth, the replace is atomic in the only sense that matters.** At every instant a runnable artifact exists at a known path, proven by injecting a failure at each of the seven normative steps (`TC-INST-030`..`TC-INST-036`), by the artifact-agreement no-op that rewrites zero artifact bytes and renames nothing (`TC-INST-022`, `TC-INST-033`), by the in-place record reconciliation for every non-`current` record condition (`TC-INST-037`), by an involutive rollback (`TC-INST-024`, `TC-INST-025`) whose slot refusal set is asserted in its normative order (`TC-INST-026`) and whose record precondition refuses an absent, unreadable, `record-stale`, and slot-silent record with zero writes (`TC-INST-042`), and by a slot that can never hold a launcher (`TC-INST-021`). **Seventh, removal is bounded and honest.** The uninstall residual set equals `purge --dry-run`'s removal set and what `purge --yes` removes, path for path, at the same moment (`TC-INST-050`, `TC-INST-051`), confirmation is required even when the roots are absent (`TC-INST-052`, `TC-INST-054`), a second removal is a reported no-op (`TC-INST-055`), and the four dry-runs leave a filesystem snapshot unchanged (`TC-INST-060`..`TC-INST-063`). **Eighth, the two residual shell surfaces keep their scope.** The installer's launcher step behaves exactly as delivered when it still owns the path (`TC-INST-090`), refuses classified and writes nothing when anything that is not the delivered launcher sits at the install path, under all three record conditions (`TC-INST-091`), and the uninstaller reports a managed install instead of touching it (`TC-INST-092`).

The plan is deliberately adversarial about the failure modes this change names. **A crash matrix that cannot fail**: an injected failure that is never reached proves nothing, so every crash case asserts both the post-failure runnable path *and* the successful recovery re-run, and the staging and verification cases assert the temporary file is gone (`TC-INST-031`, `TC-INST-032`). **A zero-write claim proven by a read**: a refusal test that only checks the exit code cannot see a write, so every refusal asserts destination bytes plus `mtimeNs`, record absence, profile-line count, and a snapshot of every state root (`TC-INST-010`, `TC-INST-013`, `TC-INST-052`, `TC-INST-080`). **A dry-run test that prints a plan but also creates the directory**: all four dry-runs compare a full snapshot of paths, sizes, `mtimeNs`, and modes (`TC-INST-060`..`TC-INST-063`). **A residual-set equality checked across two different machine states**: the three sets are computed at one instant, from one populated home (`TC-INST-051`). **A compatibility check that quietly becomes a second state read**: a planted foreign-version record below the project level must stay unread and the judged count must never exceed the declared cap (`TC-INST-045`). **A conformance gate that passes on an empty corpus**, **a family count asserted as a floor**, and **a permanent suite that diffs against a moving base branch** are all excluded by construction (§3.5, §4.4). Every guard ships a failing negative control (`TC-INST-104`); a guard without one is recorded as a gap, not a pass.

This document is a verification map, not an execution claim: no command was run against a new implementation at authoring time, and phase ownership belongs to `chg-GH-346-plan.yaml` (authored in phase 4, after this plan). All 34 acceptance criteria are covered by at least one named case; there are no TODO rows and no orphan cases. Eleven properties are observed through a declared substitute or declared-seam assertion (§3.5) because one half of the wording is a byte baseline, an injected seam the specification does not place, an operator-owned file, or an open-ended prose claim; each is recorded rather than smoothed over, and none is counted as an AC gap.

### 1.2 Out of Scope & Known Gaps

- [OUT] Performance, soak, latency, and artifact-size regressions: the artifact size is **reported and compared to a declared statement of fact**, never asserted against a threshold (`TC-BIN-063`); no suite times a lifecycle command.
- [OUT] A cross-platform or architecture matrix: the artifact targets the host it is built on (`AC-F1-2` covers the report, not a second target). No case runs a foreign-platform artifact.
- [OUT] Reproducibility assertions: `builtAt` makes byte-identical rebuilds impossible, so the only reproducibility-shaped assertion is the **negative** one — identical `--version`, different bytes, and no affirmative claim of reproducible output anywhere (`TC-BIN-063`).
- [OUT] Migration: `--migrate` detection, advisory, and typed refusal only. No case moves, copies, backs up, or converts an artifact, and no case asserts a capability M4-S2 owns (`TC-INST-075`, `TC-INST-076`).
- [OUT] Prompt, agent, and command definitions: no case drives an agent prompt, and `pnpm check:prompt` is a **control that must stay green with no edit** (NG-8).
- [OUT] Release channel, download, checksum, signature, publishing pipeline, auto-update, background version check, and any network call in the lifecycle (NG-2, NG-3; `TC-INST-014`).
- [OUT] Minification, tree-shaking, a second build path, and any CI workflow change: the artifact probe runs inside the existing Bun-bearing test job and the reviewed command list (§6.3) adds no job.
- [OUT] Multi-user, system-wide, `sudo`, shared-prefix installation, and any configurable destination: `TC-INST-006` asserts the last one is impossible, not that a parameter exists (NG-6, NG-13).
- [OUT] Daemon-pinning policy (whether a daemon must always run the installed artifact): only the replace guard and the re-entry path are asserted (NG-7).
- [OUT] Removing the managed PATH block without removing the install: no standalone verb is asserted (OQ-2).
- [OUT] Purge content estimates (file or byte counts) before confirmation: only exact paths are asserted (OQ-4).
- [OUT] Namespace migration, repository rename, package-scope change, public rebranding, and any removal or rename of the compatibility alias (NG-1, NG-9, NG-10).
- [OUT] A hard-link disposition rule at the destination: the disposition table records the declared answer; no case classifies a hard link (OQ-3, §7.2 of the spec).
- [OUT] A `doctor`/preflight surface that absorbs `install status`: no case drives one (OQ-6).
- [GAP-T1 — phase ownership belongs to the plan] `chg-GH-346-plan.yaml` owns the phase boundaries, task ownership, and per-phase test obligations. They are therefore **not** asserted here; this plan declares what must be proven.
- [GAP-T2 — the artifact identity seam is not placed by the specification] The lifecycle cases that carry an injected identity need a *running artifact that carries that identity* (SEAM-TP-1, §3.5). Whether that is reachable in-process (a declared identity-injection point) or only by executing the compiled artifact is a delivery decision (OQ-TP-3). A case that cannot resolve its seam fails naming the missing contract; it never skips.
- [GAP-T3 — the replace-step fault seam is not placed by the specification] `NFR-3`/`AC-F9-1` require a failure at each of seven steps; only the delivery can decide between a declared test-only injection point and constructed intermediate states. Both mechanisms are specified in `TC-INST-030`..`TC-INST-036`, and the constructed record conditions they also serve are in `TC-INST-037` (§3.5 `FAULT-TP-1`, OQ-TP-1).
- [GAP-T4 — CI-only gates are not observable before the pull request] `AC-F15-2`'s CI run is evidenced by the local invocation of the same script plus the delivered wiring assertions in `tests/checks/ci-checks.test.ts` (§3.5 `CI-TP-1`, OQ-TP-5).
- [GAP-T5 — delivery-bound names] Module paths for the new lifecycle code, the exact node scripts that run the build, the wording of operator lines beyond the declared content, and the exact ledger field names beyond Appendix D are delivery-bound. Behaviours, identities, exits, closed vocabularies, orderings, byte facts, and AC traceability are not.

## 3. Coverage Overview

**Numbering reconciliation (declared, not hidden).** The instruction for this plan fixes both series starts: `TC-BIN-060` for artifact/identity and `TC-INST-001` for the lifecycle. Three delivered GH-320 describes already carry `TC-BIN-060`, `TC-BIN-062`, `TC-BIN-063`, `TC-BIN-064` and `TC-BIN-067` labels (`tests/structure/entrypoint-bin.test.ts`), and the delivered installer suite tops out at `TC-BIN-057`. GH-346 identifiers are **plan-scoped**: every new describe title in a shared suite is prefixed `GH-346` (the delivered convention in those files is already `GH-320 <id>`), no delivered label is renamed, and no new case reuses a delivered GH-320 scenario. `TC-BIN-060` below is a new scenario, not a renumbering of GH-320's. This is recorded as OQ-TP-6 and is non-blocking.

## 4. Test Types and Layers

- **Structure (tree invariants), `bun:test` under `tests/structure/`** — the build entry's shape (`build:binary` declared and additive, the package build unchanged, neither installer array naming the artifact or the CLI surface), the help/coverage inventory in both directions, the error-domain rows and the two-segment allowlist, the identity-literal inventory with its two scan scopes, the ownership split between the two shell surfaces, the page set, and the delivered guards extended in place. Every guard is an exported scanner driven over a temporary tree, so a mutant is proven against the production scanner rather than a reimplementation.
- **Behaviour (composed program over the delivered seams), `bun:test` under `tests/behaviour/`** — the family surface and refusals, admission over fixture checkouts, dispositions, the replace and its artifact-agreement no-op, rollback and upgrade, the record's tolerance matrix, the compatibility verdict, the crash matrix, the three-condition reconciliation matrix, and the daemon guard. Cases drive the composed program in-process with injected identity, fake file-system port where a read must be counted, injected clock, injected daemon seam, and the delivered `readCheckoutIdentity` over real fixture checkouts — never `mock.module` of the module under test.
- **Checks — artifact-level integration, `bun:test` under `tests/checks/`** — one cached build of the change branch, consumed by cases that must observe real process facts: self-containment (3/3 in an empty directory, scrubbed `PATH`, empty `HOME`, no checkout), the four tokens, the two-build comparison, the argument-slice equivalence, the re-entry path, and `--print-install-path`. **Hermeticity rules for this layer:** the build runs once per suite run into a scratch output directory under `tmp/tmpdir/`; the artifact is invoked with an empty scratch `PATH`, scratch `HOME` and `TMPDIR` values, and a recording `git` stub where the case requires one; no case runs a network client, no case reads the operator's real `~/.jaiship`, and no case needs a checkout at run time.
- **Checks — lifecycle integration over a scratch home, `bun:test` under `tests/checks/`** — removal, the residual-set equality, the four dry-runs, the PATH block, the migration advisory, and the ownership split. These build a scratch `HOME`, config root, state root, profile file, and project root under `tmp/tmpdir/` and drive the composed program; the live `~/.jaiship`, `~/.jaiship-state`, `~/.zshrc`/`~/.bashrc`/`~/.profile`, and the real install path are only ever **snapshotted**, never written.
- **Bash, `scripts/.tests/test-*.sh`** — the two shell edits: the installer's managed-binary guard arm and the uninstaller's reporting arm, plus their preserved behaviour arms. `bash scripts/.tests/test-doc-distribution.sh` runs as the doc-distribution gate. These run with the same scratch-home discipline and `TMPDIR=$PWD/tmp/tmpdir`.
- **Metadata / gate layer** — the pinned family count and tail positions, the reference-page set, the compile-time identity site inventory, the error-table allowlist, and the aggregate gate. These are checks, not scenarios with steps: they are asserted by the structure/check cases and by the numbered commands in §6.3.
- **Measured / counted bounds** — destination byte digests and `mtimeNs`, slot digest, record digest, profile line counts, advisory line counts, judged-root counts, composer-invocation counts, `git`-stub invocation counts, temporary-file leftovers, and filesystem snapshot equality. Every absence is proven three ways per the house discipline: a recording seam or armed counter, a zero count, and an unchanged durable artifact (digest, mtime, or snapshot).
- **Not used:** `mock.module` substitution of the module under test; real network; the operator's real `$HOME` as state; the real install path as a fixture; real sleeps; a performance or soak measurement; a foreign-platform artifact; `sudo`; any write outside a scratch root.

### 4.1 Hermeticity and determinism

Every case in this plan obeys five rules, and a case that cannot is a gap, not a warning:

1. **Scratch `HOME`.** `HOME` is a `mkdtemp` directory under `tmp/tmpdir/` for every case that drives a lifecycle command. Brand path derivation is exercised through the resolver (`--print-install-path`), never by writing the operator's home.
2. **Scratch project root.** Fixture checkouts, clones, and linked worktrees live under the scratch root; the fixture **shape** (a committed worktree topology) is created by the case, not committed as a nested git repository.
3. **No mutation of the live state.** `~/.jaiship`, `~/.jaiship-state`, `~/.local/bin`, and the three real profile files are never written. Cases that must prove this snapshot them (paths, sizes, `mtimeNs`, modes) before and after and assert equality.
4. **`TMPDIR=$PWD/tmp/tmpdir` on every recorded gate command** (§6.3), and the same directory as the base for in-test scratch roots, so a repo-local run is deterministic and a same-device temp directory is used (the delivered precedent in `tests/checks/install-launcher-installer.test.ts`).
5. **Offline.** No case constructs a network client, spawns `curl`/`wget`, or runs `git fetch|pull|clone`. Where a network-capable binary could be reached through `PATH`, a recording shim proves it was not invoked. The artifact build itself is offline.

Determinism: no case asserts wall-clock timing (the delivered isolation suite's `elapsedMs` check is informational and is not copied); no case asserts directory-iteration order; `install status` output is compared between two runs of the same machine state as an ordered sequence of lines and as an ordered JSON field list (`TC-INST-046`).

### 4.2 Zero-write proofs

Three mechanisms, used according to the claim:

| Claim | Mechanism |
|---|---|
| A refused operation wrote nothing | Destination content digest plus `mtimeNs` unchanged; record path absent (or unchanged); profile line count unchanged; every state root snapshot unchanged; no temporary file left in the install directory (`TC-INST-010`, `TC-INST-013`, `TC-INST-052`, `TC-INST-080`). |
| A dry-run wrote nothing | A full snapshot of the declared roots — **paths, sizes, `mtimeNs`, modes** — captured before and compared after, plus a directory-creation count of zero and a daemon-action log of zero (`TC-INST-060`..`TC-INST-063`). |
| An install added nothing to the state layer | The state-root snapshot is unchanged before and after, and no `header.*.json`, ledger, or manifest is created; the record lives in the config root, never in a state root (`TC-INST-040`, `TC-INST-045`). |

A snapshot is a sorted array of `relative-path|size|mtimeNs|mode` lines, so a content-preserving rewrite that changes mtime or mode still fails. `mtimeNs` is read with `statSync(path, { bigint: true }).mtimeNs`; a platform that cannot supply nanosecond precision is a declared gap in §10, never a silent downgrade to seconds.

### 4.4 Invariant rules for permanent suites

- **No permanent suite asserts a diff against a moving base branch.** No case reads `origin/main-tools...HEAD`, no case asserts an exact changed-file set, and no case asserts "exactly one changeset added". Branch-shape ideas are converted to tree invariants: the declared artifact path exists and is ignored, the pinned counts are exact, the page set is exact, the inventory is exact.
- **Pinned counts that are delivered contracts are asserted exactly and by name.** The family count (26), the family-tail identity (`install` last, `supervise` immediately before it), the two-segment allowlist (66), and the identity-literal inventory (five product-surface sites plus one declared build-side site) are equality assertions. A floor would pass while the contract was broken.
- **Snapshots and goldens that pin preserved data move deliberately.** The only baseline fixtures this change touches are the help/coverage inventory and the result corpora; each is edited as a declared delta, never regenerated by blanket rewrite.
- **A rule without a failing fixture is a gap.** Every new guard ships its mutant in the same change (§4.3); a guard whose control is deferred is recorded in §8, not counted as covered.
- **Assert the value's meaning, not a growing count.** Where a population is expected to grow (advisory lines per root, judged roots below the cap), the assertion is a relation (`one per not-accepted root`, `≤ cap and equal to the capped count`), not a magic total.

### 6.3 Gate battery (numbered) and evidence shape

Every command runs from the repository root with the scratch temp directory, in this order. Gate 0 is optional: the artifact tier builds what it needs inside gate 1, and no gate depends on gate 0.

```bash
# 0. OPTIONAL manual pre-warm only — never a dependency. The artifact tier self-builds
#    one artifact per suite run in a scratch output directory (plus one extra build for
#    the two-build byte comparison), so `pnpm check` is green without this command, and
#    the recorded evidence below does not claim it.
TMPDIR=$PWD/tmp/tmpdir bun run build:binary

# 1. Aggregate gate (the single quality gate)
TMPDIR=$PWD/tmp/tmpdir pnpm check

# 2. Narrow re-run of the changed-tier suites (for iteration and for the evidence count)
TMPDIR=$PWD/tmp/tmpdir bun test 'tests/behaviour/install-*.test.ts' 'tests/checks/install-*.test.ts' 'tests/checks/artifact-*.test.ts' 'tests/structure/install-*.test.ts' 'tests/structure/build-artifact-entry.test.ts'

# 3. Installer shell suite (new guard arm)
TMPDIR=$PWD/tmp/tmpdir bash scripts/.tests/test-install.sh

# 4. Uninstaller shell suite (new reporting arm)
TMPDIR=$PWD/tmp/tmpdir bash scripts/.tests/test-uninstall.sh

# 5. Doc-distribution guard (ships redistributable docs)
TMPDIR=$PWD/tmp/tmpdir bash scripts/.tests/test-doc-distribution.sh

# 6. The CI error-table gate, run locally with the same script CI runs (deliberately not in pnpm check)
TMPDIR=$PWD/tmp/tmpdir bun run scripts/checks/error-table-sync.ts

# 7. Supplementary range gate (pre-PR commit-message check)
TMPDIR=$PWD/tmp/tmpdir ./scripts/lint-commit-range.sh --base main-tools
```

Evidence record (pm-notes `notes:` entry; `type` is a free-form string validated only for presence alongside `text`, so `evidence` is schema-valid; use `info` if a future lint narrows the vocabulary):

```yaml
- text: >-
    quality_gates evidence: gates 1-7 PASS (gate 0 is an optional manual pre-warm no gate depends on) —
    pnpm check (all tests, 0 fail; the artifact tier self-built its own artifact: one cached build per
    suite run plus one extra for the two-build comparison; size and host target reported);
    narrow tier (pass count / total); test-install.sh (pass count);
    test-uninstall.sh (pass count); test-doc-distribution.sh PASS; error-table-sync PASS
    (66 two-segment identities, 11 install rows); lint-commit-range PASS;
    commit = the change-branch head the gates ran against; verdict PASS
  type: evidence
  date: "2026-11-18"   # the run date
```

Rules for the record: one entry per gate that moved a verdict; a `FAIL` names the failing suite and the remediation mode; an unresolved `ERROR` is recorded as `ERROR` and never rounded to `PASS`; the allowlist count and the family count are stated as exact numbers; the commit is the change-branch head the gates ran against.

## 8. Risks, Assumptions, and Open Questions

### 8.1 Risks

| ID | Risk to this plan | Mitigation |
|---|---|---|
| TR-1 | The artifact tier is slow (~107 MB build) and becomes flaky or skipped under time pressure | The tier self-builds one artifact per suite run into a scratch output directory, plus one extra build for the byte comparison; the artifact tier is a small declared file set; a failed build fails the tier by name. The suite never silently skips (SEAM-TP-1), and no gate command has to pre-warm it. |
| TR-2 | The in-process identity seam does not exist, so thirteen lifecycle cases escalate to the artifact tier | OQ-TP-3 is raised before delivery; the escalation path is declared and its cost recorded in §10 rather than hidden. |
| TR-3 | No fault-injection mechanism exists, so the crash matrix degrades to constructed states | FAULT-TP-1 defines the primary and fallback mechanisms; a step that cannot be induced fails by name. |
| TR-4 | The pin-scan suites (`supervision-mounting`, `metrics-mounting`) have their own staleness regexes, so a partial count move leaves a stale pin | `TC-INST-100` asserts every `PINNING_FILES` member carries the 26 pin and no stale 25, and the delivered scanners are the assertion's input, not a reimplementation. |
| TR-5 | Two copies of the page-root mapping (`scripts/checks/help-guide-coverage.ts` and `tests/checks/reference-page-parity.test.ts`) drift | Both move in the same phase; `TC-INST-102` asserts the mapping resolves the page, and `TC-INST-103` asserts the inventory agrees. |
| TR-6 | The compatibility check grows into a second state read | READ-TP-1's canary plus the state-root snapshot plus the unchanged hard-gate suite; a widened read fails the canary arm. |
| TR-7 | Snapshot equality flakes because a background process touches a scratch root | Every process the case starts is waited for; scratch roots are unique per case; the daemon is an injected seam, not a real process. |
| TR-8 | The documentation phrase tables become a rubber stamp | Both directions are asserted with a negative control per direction, and the page set is exact, so a new claim cannot be added without a failing case (DOC-TP-1). |
| TR-9 | A behaviour-tier case wires steps 2/3 to `process.execPath`, so an in-process install stages the Bun binary and the failure reads as a product defect | `runningArtifactPath` is a declared composition fact (SEAM-TP-1, §6.2): the fixture artifact's path travels with the injected identity, `TC-INST-011` asserts the destination holds the fixture artifact's bytes, and a composer that cannot resolve the fact fails the case by name instead of falling back. |
| TR-10 | The error-table total moves across nine suites and two page phrases, and a partial move leaves the sync gate red at the phase boundary | §7.2 names every site and its move; `TC-INST-106` asserts source, documented, corpus, and page as one set; the §7.2 paragraph states the half-move is a gate failure, not a green. |

### 8.2 Assumptions

- The pinned Bun toolchain compiles the primary bin into a working self-contained executable, `--define` injects a compile-time constant a presence guard can detect, and the compiled `argv` slice still yields exactly the user arguments (spec §12; measured before the specification was written).
- `readCheckoutIdentity` remains the delivered source of the own-git-directory and common-git-directory facts, so admission needs no new process shape.
- A store header is the only file the store writes with the format identifier, and the host root has one directory per project beneath it.
- The delivered daemon exposes a readable instance and stop path that an injected seam can model faithfully enough for the ordering assertion.
- The delivered launcher's rendered content is distinguishable from a compiled artifact, so the disposition table is decidable.
- The operator's profile file is writable and identifiable when `--add-to-path` is requested.
- Tick counts and vocabulary items in the delivered suites are the contracts this change moves; no other suite pins a family count outside `PINNING_FILES`.
- `pnpm check` keeps its shape: the artifact build and the error-table sync do not join it (§12 of the spec).
