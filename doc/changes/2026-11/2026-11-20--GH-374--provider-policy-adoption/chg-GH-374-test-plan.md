# Test Plan - M4-S16: Provider policy adoption in this repository (M4)

## 1. Scope and Objectives

This change adds no capability, so the risk is not a missing command — it is a policy that is *described* as adopted while the document, a seat, a chain or a guide says something else. Every claim is therefore pinned as a comparison a suite runs against the **real** committed document (never a fixture copy of the policy) or against a scratch checkout seeded with a byte copy of it. **First, the declaration loads and is the declaration.** The provider and profile branches parse and validate through the delivered validator, both chains validate, `defaultChain` names `subscription-first`, the two entries carry their declared classes, peaks and quota block, both ceilings and both profiles are exactly the decided values, every effective provider value reports `.delivery-os/config.yaml` with a line as its origin, and five document mutations (subscription after paid, unknown entry reference, unknown credential reference, unknown default chain, empty chain) refuse with the delivered `provider.chain.invalid` / `provider.chain.empty` naming the field (`TC-POL-CFG-001`..`TC-POL-CFG-009`, `TC-POL-DRIFT-006`). **Second, every role has a seat on both profiles.** Twenty-four roles resolve a seat, a `--for-spawn` `data-v1` env record inside the 256-record / 65,536-byte bounds with names derived from the brand prefix, and a per-spawn binding naming the declared model, with zero `unassigned`, zero vision-capable seat on a text-only model, and an identical capability per seat across the two profiles (`TC-POL-SEAT-001`..`TC-POL-SEAT-006`). **Third, the policy replays offline.** Six committed fixtures reproduce peak parking, exhausted-quota parking with the reset instant, a trailing-window budget park with a strictly future computed expiry, subscription-first selection with `shadowed`, the declared paid fallback, and the ticket-ceiling refusal — each in the delivered chain-park shape beside the provider park, with `stateWrites: 0`, byte-identical repeats and zero credential, transport, state or spawn effect (`TC-POL-SIM-001`..`TC-POL-SIM-009`).

**Fourth, the dependency is gone and the proof cannot be vacuous.** The scan declares its include and exclude sets, reports zero findings over the real tree, detects one planted sample per forbidden class, does not report the allowed opt-in invocation idiom, fails on an empty include set, and reports a planted literal from `.opencode/agent/**` (`TC-POL-SCAN-001`..`TC-POL-SCAN-005`). **Fifth, drift fails by name.** A permanent reference test reads the real document, compares each profile's seat set against the roster read from `.opencode/agent/` in both directions, re-parses the real document through the delivered validator so a zero-buffer window fails the load, and fails on each of seven named mutants (`TC-POL-DRIFT-001`..`TC-POL-DRIFT-007`). **Sixth, documentation is part of the contract.** Three guides carry the adopted policy and its limits as required sentences behind a closed stale set, keep valid `ados_distribution` markers and pass the distribution guard (`TC-POL-DOC-001`..`TC-POL-DOC-005`). **Seventh, admission is evidenced without a second delivery.** The nomination predicate over the real configuration returns `delivery`, `provider.profile.absent` is not producible from this checkout, the pause refusals name their blockers, the seat/binding/env-record proofs agree across surfaces, and no real `dispatch` is run (`TC-POL-NOM-001`..`TC-POL-NOM-004`). **Eighth, the bridge is recorded and the boundary is clean.** The two migration refusals are asserted as evidence while the migrator's owned surfaces stay pinned, no suite re-runs the migration against an operator home, and a canary credential never reaches any surface (`TC-POL-MIG-001`..`TC-POL-MIG-003`, `TC-POL-SEC-001`..`TC-POL-SEC-003`).

This document is a verification map, not an execution claim: nothing was run against a new implementation at authoring time, and phase ownership belongs to `chg-GH-374-plan.yaml`, authored in phase 4 after this plan. All **15** acceptance criteria are covered by at least one named case, and every one of the **52** cases names at least one criterion — no TODO rows, no orphans. The properties this change does *not* prove are declared in §1.2 and §3.5 rather than smoothed over: no real dispatch, no live quota or balance read, no daemon lane watch, no performance measurement, and no diff-against-a-moving-base assertion in a permanent suite. The three specification open questions (`OQ-1`, `OQ-2`, `OQ-3`) are cited where a case depends on the delivered behaviour they describe; no new question is opened.

### 1.2 Out of Scope & Known Gaps

- [OUT] **Any real `dispatch`.** `dispatch GH-374` would claim the repository lease and start a second delivery of this change. Admission is evidenced by the nomination predicate, the pause refusals, and the seat/binding/env-record proofs (`TC-POL-NOM-001`..`TC-POL-NOM-004`; DEC-13, A-9). The plan and the pull request state the reason; `TC-POL-NOM-003` asserts that record.
- [OUT] **Any live quota or balance read.** The synchronous nomination probe reads neither; `provider watch status` is exercised only with an injected transport and fixture bodies (`TC-POL-CFG-010`), and `TC-POL-NOM-001` asserts the nomination path calls no transport and no credential port. Live pre-selection verification belongs to the daemon path (F-5, DEC-11, RSK-9) and is not claimed.
- [OUT] **The daemon lane watch.** Profile `peakWindows` are declared rule data that drive a watch this composition does not mount; no case asserts their participation in admission, and `TC-POL-CFG-009` asserts the delivered truth that they do not (OQ-1).
- [OUT] **Weekday, holiday, or calendar semantics.** The declared windows are daily; `TC-POL-CFG-009` and `TC-POL-DOC-001` assert the daily superset and the weekend consequence, and the deferred weekday dimension stays with OQ-2. No case asserts a weekday exemption.
- [OUT] **The 04:00–06:00 capacity cost as a throughput measurement.** `TC-POL-CFG-009` asserts the exact closed interval; the policy trade-off and its remedy are stated in the specification, the guide and OQ-3, not measured.
- [OUT] **Any migrator behaviour change or re-run.** `provider migrate legacy` keeps its grammar, caps, reasons and output; no case or gate re-runs it against an operator home (`TC-POL-MIG-001`..`TC-POL-MIG-003`; NG-2, RSK-13).
- [OUT] **Any engine, package, prompt, or other-configuration change.** No case drives one, and `TC-POL-DRIFT-007`, `TC-POL-MIG-002` and the pre-PR locality gate (`G8`) pin the boundary (NFR-7, NG-1, NG-5).
- [OUT] **Diff-shaped assertions inside permanent suites.** A permanent suite asserts the current tree or HEAD; "only these files changed" and "the migrator's bytes are unchanged relative to `main-tools`" are pre-PR review gates (`G8`) plus the content pins of `TC-POL-MIG-002`, per `.ai/rules/testing-strategy.md` §"Invariant-test authoring" (`GIT-TP`).
- [OUT] **Performance, latency and read-cost measurement.** `TC-POL-CFG-005` asserts a read **count** of one, never a duration.
- [GAP-T1 — phase ownership belongs to the plan] `chg-GH-374-plan.yaml` owns phase boundaries, per-phase test obligations and commit granularity. They are not asserted here; this plan declares what must be proven.
- [GAP-T2 — an `envName` literal is not committed] The ticket lists `envName` among the seat fields; the declaration omits it, so each record name is derived from the brand's environment prefix (DEC-7). Every case asserts the **record-level** requirement — `OC_JAISHIP_AGENT_<SEAT>_MODEL` in the `--for-spawn` record — and no case asserts a committed literal (`TC-POL-SEAT-003`).
- [GAP-T3 — delivery-bound names] Module paths and seam names beyond the delivered entry points named in §2 are delivery-bound. Behaviours, identities, exits, closed vocabularies, orderings, instants and AC traceability are not.
- [GAP-T4 — the range gate and the CI run are not observable before the pull request] `./scripts/lint-commit-range.sh --base main-tools` is invoked locally as the same check CI mirrors (`G7`), and `pnpm check` is the aggregate (`G5`); the verdicts are recorded in §10.

### 4.1 Hermeticity and determinism

Every case obeys six rules, and a case that cannot is a gap, not a warning:

1. **Scratch checkout and scratch home.** Every composed case materialises a checkout and a home under `$PWD/tmp/tmpdir` (`makeTempRoot` from the delivered state harness or the suite's own `mkdtemp`), copies the real document byte-for-byte into the prior configuration directory, and never writes the repository or the operator's home.
2. **Zero read of the operator's real roots.** `~/.jaiship`, `~/.jaiship-state`, `~/.delivery-os`, `~/.delivery-os-state` and the operator's real `~/.ados` profile directory and hook are never written **and never read**. Where a zero-read claim is made it is proven by a recording file-access stub (`READ-TP`), whose own non-vacuity arm records a planted read.
3. **No real `provider migrate` and no `$HOME` target.** The two refusals are evidence read from `migration-output.md`; no case invokes `provider migrate` against a real home, and the legacy-present arm of `TC-POL-CFG-002` materialises *benign synthetic* assignments in the scratch home, never the operator's files.
4. **No wall clock and no real sleep.** Time enters only through an injected `clock` (fixed instants: 02:00Z, 03:30Z, 04:00Z, 04:30Z, 05:00Z, 09:59Z, 10:00Z, 12:00Z, Saturday 05:00Z, plus the fixture `now` values). A case that advances time advances the injected clock and asserts a zero sleep count.
5. **No live network and no live credential.** The quota transport is replaced by fixture facts (simulate) or by a recording/throwing fake (watch, resolve); credential outcomes are the closed `resolved | missing | rejected` enum; the canary value exists only inside a case's injected credential port.
6. **`TMPDIR=$PWD/tmp/tmpdir` on every recorded gate command** (§6.3) and as the base for every in-test scratch root; every temporary root is removed at case end.

Determinism: no case asserts wall-clock timing, directory-iteration order, or a diff against a moving base. Where the population is open-ended (the number of scanned files, the number of seats per profile) the assertion is an exact declared count (`24`, and the roster read in both directions) or a relation (`one read`, `one condition per target`), never a growing floor.

| Claim | Mechanism |
|---|---|
| A replay wrote no state | State-root snapshot (paths, sizes, `mtimeNs`, modes, digests) before and after; `simulation.stateWrites === 0`; a throwing state store that fails the case if written; `TC-POL-SIM-007`. |

### 4.4 Invariant rules for permanent suites

- Permanent suites assert the current tree or HEAD. `DRIFT-005` mutates a **copy** under `tmp/tmpdir` and runs the same pinned assertions over it; it never writes the committed document.
- The roster is read from `.opencode/agent/*.md` at assertion time, never transcribed into the suite. The **expected** seat set is the file set; `DRIFT-002` asserts equality in both directions so a new agent and a stale seat both fail.
- The declared counts (`24` seats per profile, `2` chains, `2` credentials, `2` budgets, `2` profiles, `2` watch targets) are asserted exactly and by name, never as floors: a floor cannot detect the regression the pin exists to catch.
- No `mock.module`; no subprocess; no ambient environment read. Every fact is an injected value or a file under a scratch root.
- Adding a test file needs no suite-map edit: `tests/**` is already in the aggregate `tests` suite, and `DRIFT-007` asserts the committed `verify.suite-map` declaration is unchanged.

```bash
# 6. The documentation distribution guard
bash scripts/.tests/test-doc-distribution.sh

# 7. Supplementary range gate (pre-PR commit-message check)
./scripts/lint-commit-range.sh --base main-tools

# 8. Pre-PR locality check (review gate, not a permanent suite: GIT-TP)
git diff --name-only main-tools...HEAD
```

`G8` records the declared file set and must show only: `.delivery-os/config.yaml`, the six simulate fixtures, the five new suites plus the extended `doc-conformance`, the three guides, `migration-output.md`, and this change folder. Evidence record (pm-notes `notes:` entry; `type` is a free-form string validated only for presence alongside `text`, so `evidence` is schema-valid; use `info` if a future lint narrows the vocabulary):

```yaml
- text: >-
    quality_gates evidence: gates 1-8 PASS —
    reference suite (seed set asserted, 7/7 drift mutants fail by name, roster 24/24 both directions,
```

Rules for the record: one entry per gate that moved a verdict; a `FAIL` names the failing suite and the remediation mode; an unresolved `ERROR` is recorded as `ERROR` and never rounded to `PASS`; counts are exact numbers; the commit is the change-branch head the gates ran against.
