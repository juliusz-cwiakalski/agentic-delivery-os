# Test Plan - M4-S16: Provider policy adoption in this repository (M4)

## 1. Scope and Objectives

This change adds almost no capability, so the risk is not a missing command — it is a policy that is *described* as adopted while the document, a seat, a chain, a prompt or a guide says something else. Every claim is therefore pinned as a comparison a suite runs against the **real** committed document (never a fixture copy of the policy) or against a scratch checkout seeded with a byte copy of it. **First, the declaration loads and is the declaration.** The provider and profile branches parse and validate through the delivered validator, both chains validate, `defaultChain` names `subscription-first`, and **declared** values are pinned separately from the **delivered defaults** they merge with: the document's own entry body is deep-equalled with no extra keys, while the resolved entry additionally carries the four shipped quota leaves (`timeoutMs` 15000, `outageParkTtlSeconds` 300, `credentialParkTtlSeconds` 900, `capParkTtlSeconds` 300) whose origins report `layer=defaults`. A single resolved node is never deep-equalled against a literal that omits them (`TC-POL-CFG-006`, `TC-POL-DRIFT-001`, `TC-POL-DRIFT-006`; the DoR M1 finding). Six document mutations — subscription after paid, unknown entry reference, **duplicate entry**, unknown credential reference, unknown default chain, empty chain — refuse with the delivered `provider.chain.invalid` / `provider.chain.empty` identities whose **detail prose** names the offending chain, entry, credential or default chain; chain errors carry no `field` member, so no case invents one, while a profile defect's `field` and a budget defect's detail path are asserted where the validator actually supplies them (`TC-POL-CFG-004`; the DoR M3 finding).

**Second, every role has a seat on both profiles, and the vision proof names its agent.** Twenty-four roles resolve a seat, a `--for-spawn` `data-v1` env record inside the 256-record / 65,536-byte bounds with names derived from the brand prefix, and a per-spawn binding naming the declared model, with zero `unassigned`, zero vision-capable seat on a text-only model, and an identical capability per seat across the two profiles. The capability arm drives `selectProfile({ requireVision: true, agent })` for `designer` **and** `image-reviewer`, because an agent-less vision resolution resolves the alphabetically first seat (`bootstrapper`, a text-only z.ai seat) and is denied; that agent-less outcome is asserted as a **known trap**, never used as the oracle (`TC-POL-SEAT-001`..`TC-POL-SEAT-006`; the DoR M12 finding).

**Third, the policy replays offline, and the two ceilings cannot be confused.** The trailing-day ceiling is **20** and the ticket ceiling is **30**, because a `failed` condition outranks every `parked` one: at 25 the entry parks on the window scope while the ticket scope stays clear, and at 30 the ticket scope fails and the command refuses. No single figure is asserted as both parked and skipped, and the ordering is itself a pinned, mutation-tested invariant (`TC-POL-SIM-003`, `TC-POL-SIM-006`, `TC-POL-DRIFT-004`; the DoR B2 finding). Six committed fixtures reproduce peak parking, exhausted-quota parking with the reset instant, the trailing-window park, subscription-first selection with `shadowed`, the declared paid fallback, and the ticket stop — each in the delivered chain-park shape beside the provider park, with `stateWrites: 0`, byte-identical repeats and zero credential, transport, state or spawn effect.

**Fourth, the dependency is gone, the prompt claim is true of the tree, and neither proof can be vacuous.** The delivery-surface scan declares its include set **and every exclusion**, reports zero findings, detects one planted sample per source class, does not report the allowed invocation or `scripts/install.sh`'s declared example copy, fails on an empty include set, and proves the second half: the adopter blueprint is the only file installing at the `pre-opencode-iteration` path and no delivery-surface file references it (`TC-POL-SCAN-001`..`TC-POL-SCAN-003`, `TC-POL-SCAN-005`). A **separate** full-roster prompt scan covers all 24 prompts for provider-qualified expressions and model-family ids used as values, with one planted control per class, a bare-family-prose exclusion and the documented `claude.model` carve-out; a regression arm proves the scan reports the **pre-change** toolsmith identifiers, and the generated `.ados-claude/agents/toolsmith.md` is proven build output with a second build a no-op (`TC-POL-SCAN-004`, `TC-POL-SCAN-006`, `TC-POL-SCAN-007`; the DoR B1 finding).

**Fifth, drift fails by name.** A permanent reference test reads the real document, compares each profile's seat set against the roster read from `.opencode/agent/` in both directions, re-parses the real document through the delivered validator so a zero-buffer window fails the load through `peakWindows.graceSeconds`, and fails on each of **eight** named mutants — removed seat, changed model, new agent, reordered chain, narrowed peak, changed ceiling, **inverted ceiling ordering**, zero buffer (`TC-POL-DRIFT-001`..`TC-POL-DRIFT-007`). **Sixth, documentation is part of the contract.** Three guides state the adopted policy and its limits, the repository-facing reference states the canonical routing path and that no provider/model identifier belongs in a prompt, and the one contradicted current-truth sentence in `feature-provider-profiles.md` is pinned as a required/stale pair; every edited page keeps a valid `ados_distribution` marker and the distribution guard passes (`TC-POL-DOC-001`..`TC-POL-DOC-006`).

**Seventh, admission is evidenced without a second delivery, and the substitution is stated.** The nomination predicate over the real configuration returns `delivery`, `provider.profile.absent` is not producible, the pause refusal is asserted as `ok === false` plus the exact `"<profile>:ineligible:<blockerKind>+…"` string array it returns (blocker **values** are asserted on the composed `provider profile resolve` arm), the seat/binding/env-record proofs agree across surfaces, and no real `dispatch` is run — the ticket's typed-attempt half is recorded as a declared substitution, so the trace is four of five fully plus one partial (`TC-POL-NOM-001`..`TC-POL-NOM-004`; the DoR M4 finding). **Eighth, the bridge is recorded and the boundary is clean.** The two migration refusals are asserted as evidence while the migrator's owned surfaces stay pinned, no suite re-runs the migration against an operator home, every credential node is exactly `{sourceKey: {style, name}}`, a canary credential never reaches any surface, and documentation placeholders are carved out of the credential-shaped scan by an explicit rule with a control in both directions (`TC-POL-MIG-001`..`TC-POL-MIG-003`, `TC-POL-SEC-001`..`TC-POL-SEC-003`; the DoR M5/M6 findings).

This document is a verification map, not an execution claim: nothing was run against a new implementation at authoring time, and phase ownership belongs to `chg-GH-374-plan.yaml`, authored in phase 4 after this plan. All **15** acceptance criteria are covered by at least one named case, and every one of the **55** cases names at least one criterion — no TODO rows, no orphans, one owner per case. The properties this change does *not* prove are declared in §1.2 and §3.5 rather than smoothed over: no real dispatch (the typed-attempt half is substituted, not observed), no live quota or balance read, no daemon lane watch, no performance measurement, and no diff-against-a-moving-base assertion in a permanent suite. The three specification open questions (`OQ-1`, `OQ-2`, `OQ-3`) are cited where a case depends on the delivered behaviour they describe; no new question is opened.

### 1.2 Out of Scope & Known Gaps

- [OUT] **Any real `dispatch`.** `dispatch GH-374` would claim the repository lease and start a second delivery of this change. The admission half is evidenced by the nomination predicate, the exact refusal shape, and the seat/binding/env-record proofs; the ticket's **typed-attempt half is not observed** and is recorded as a declared substitution (four of five ticket clauses fully traced, one partial) in the plan and the pull request (`TC-POL-NOM-001`..`TC-POL-NOM-004`; DEC-13, A-9; AC-F7-3; the DoR M9 finding). No case claims a typed attempt record.
- [OUT] **Any live quota or balance read.** The synchronous nomination probe reads neither; `provider watch status` is exercised only with an injected transport and fixture bodies (`TC-POL-CFG-010`), and `TC-POL-NOM-001` asserts the nomination path calls no transport and no credential port. Live pre-selection verification belongs to the daemon path (F-5, DEC-11, RSK-9) and is not claimed.
- [OUT] **The daemon lane watch.** Profile `peakWindows` are declared rule data that drive a watch this composition does not mount; no case asserts their participation in admission, and `TC-POL-CFG-009` asserts the delivered truth that they do not (OQ-1).
- [OUT] **Weekday, holiday, or calendar semantics.** The declared windows are daily; `TC-POL-CFG-009` and `TC-POL-DOC-001` assert the daily superset (weekends and Chinese public holidays additionally paused) and the deferred weekday dimension stays with OQ-2. No case asserts a weekday exemption.
- [OUT] **The 04:00–06:00 cost as a throughput measurement.** `TC-POL-CFG-009` asserts the exact closed **time-of-day interval**; the weekend/holiday superset and the policy trade-off are stated in the specification, the guide and OQ-3, not measured.
- [OUT] **Any migrator behaviour change or re-run.** `provider migrate legacy` keeps its grammar, caps, reasons and output; no case or gate re-runs it against an operator home (`TC-POL-MIG-001`..`TC-POL-MIG-003`; NG-2, RSK-13).
- [OUT] **Any engine, package, command, or other-prompt change.** The only prompt files in scope are `.opencode/agent/toolsmith.md` and its regenerated `.ados-claude/agents/toolsmith.md`; every other prompt and command definition is untouched, and `TC-POL-DRIFT-007`, `TC-POL-MIG-002` and the pre-PR locality gate (`G8`) pin the boundary (NFR-7, NG-1, NG-5; DEC-20).
- [OUT] **A hand-edited generated plugin.** `TC-POL-SCAN-006` proves the generated file is build output and a second build is a no-op; a hand edit fails the provenance/containment arms rather than being accepted (RSK-17).
- [OUT] **Diff-shaped assertions inside permanent suites.** A permanent suite asserts the current tree or HEAD; "only these files changed" and "the migrator's bytes are unchanged relative to `main-tools`" are pre-PR review gates (`G8`) plus the content pins of `TC-POL-MIG-002`, per `.ai/rules/testing-strategy.md` §"Invariant-test authoring" (`GIT-TP`).
- [OUT] **Performance, latency and read-cost measurement.** `TC-POL-CFG-005` asserts a read **count** of one, never a duration.
- [OUT] **Real secret values.** No case, fixture or document carries one. The credential-shaped scan covers real values only and carves documentation placeholders out by an explicit rule with a control in both directions (`TC-POL-SEC-003`; the DoR M6 finding).
- [GAP-T1 — phase ownership belongs to the plan] `chg-GH-374-plan.yaml` owns phase boundaries, per-phase test obligations and commit granularity. They are not asserted here; this plan declares what must be proven. The plan's own suite list and phase-1 gate are delivery-planning remediation items and are expected to align to spec v1.4; this plan follows the **specification's** closed file set.
- [GAP-T2 — an `envName` literal is not committed] The ticket lists `envName` among the seat fields; the declaration omits it, so each record name is derived from the brand's environment prefix (DEC-7), and the deviation is on the PR's owner-review list. Every case asserts the **record-level** requirement — `OC_JAISHIP_AGENT_<SEAT>_MODEL` in the `--for-spawn` record — and no case asserts a committed literal (`TC-POL-SEAT-003`).
- [GAP-T3 — delivery-bound names] Module paths and seam names beyond the delivered entry points named in §2 are delivery-bound. Behaviours, identities, exits, closed vocabularies, orderings, instants and AC traceability are not.
- [GAP-T4 — the build, the range gate and the CI run are not observable from a stale worktree] `pnpm build` is gate `G0` (the workspace packages export from `dist/`), `./scripts/lint-commit-range.sh --base main-tools` is invoked locally as the same check CI mirrors (`G7`), and `pnpm check` is the aggregate (`G5`); the verdicts are recorded in §10 (the DoR M8 finding).

## 3. Coverage Overview

All **15** acceptance criteria map to at least one named case, and no case is an orphan. The plan carries **55 cases** in nine blocks: **10** configuration cases (`TC-POL-CFG-001`..`010`), **6** seat cases (`TC-POL-SEAT-001`..`006`), **9** replay cases (`TC-POL-SIM-001`..`009`), **7** scan and prompt cases (`TC-POL-SCAN-001`..`007`), **7** drift cases (`TC-POL-DRIFT-001`..`007`), **6** documentation cases (`TC-POL-DOC-001`..`006`), **4** nomination cases (`TC-POL-NOM-001`..`004`), **3** migration cases (`TC-POL-MIG-001`..`003`) and **3** credential-safety cases (`TC-POL-SEC-001`..`003`). The blocks are deliberately feature-scoped rather than file-scoped, so a case keeps its id if a suite is split. Every new `describe` title in a shared suite is prefixed `GH-374`, and no delivered label is renamed.

### 4.1 Hermeticity and determinism

Every case obeys seven rules, and a case that cannot is a gap, not a warning:

1. **Scratch checkout and scratch home.** Every composed case materialises a checkout and a home under `$PWD/tmp/tmpdir` (`makeTempRoot` from the delivered state harness or the suite's own `mkdtemp`), copies the real document byte-for-byte into the prior configuration directory, and never writes the repository or the operator's home.
2. **Zero read of the operator's real roots.** `~/.jaiship`, `~/.jaiship-state`, `~/.delivery-os`, `~/.delivery-os-state` and the operator's real `~/.ados` profile directory and hook are never written **and never read**. Where a zero-read claim is made it is proven by a recording file-access stub (`READ-TP`), whose own non-vacuity arm records a planted read.
3. **No real `provider migrate` and no `$HOME` target.** The two refusals are evidence read from `migration-output.md`; no case invokes `provider migrate` against a real home, and the legacy-present arm of `TC-POL-CFG-002` materialises *benign synthetic* assignments in the scratch home, never the operator's files.
4. **No wall clock and no real sleep.** Time enters only through an injected `clock` (fixed instants: 02:00Z, 03:30Z, 04:00Z, 04:30Z, 05:00Z, 09:59Z, 10:00Z, 12:00Z, Saturday 05:00Z, plus the fixture `now` values). A case that advances time advances the injected clock and asserts a zero sleep count.
5. **No live network and no live credential.** The quota transport is replaced by fixture facts (simulate) or by a recording/throwing fake (watch, resolve); credential outcomes are the closed `resolved | missing | rejected` enum; the canary value exists only inside a case's injected credential port.
6. **`TMPDIR=$PWD/tmp/tmpdir` on every recorded gate command** (§6.3) and as the base for every in-test scratch root; every temporary root is removed at case end.
7. **One sanctioned no-op build.** `TC-POL-SCAN-006` snapshots every `.ados-claude/**` digest, runs the delivered `scripts/build-claude-plugin.sh` at the repository root, and asserts the snapshot is byte-identical and `git status --porcelain -- .ados-claude .opencode` is empty. The build is the *only* repository write any case may cause, it is proven to write nothing, and a stale pair **fails the case** rather than being committed. Precedent: the delivered `tests/checks/milestone-prompts.test.ts` performs the same second build.

Determinism: no case asserts wall-clock timing, directory-iteration order, or a diff against a moving base. Where the population is open-ended (the number of scanned files, the number of seats per profile) the assertion is an exact declared count (`24`, and the roster read in both directions) or a relation (`one read`, `one condition per target`), never a growing floor.

### 4.4 Invariant rules for permanent suites

- Permanent suites assert the current tree or HEAD. `DRIFT-005` mutates a **copy** under `tmp/tmpdir` and runs the same pinned assertions over it; it never writes the committed document.
- The roster is read from `.opencode/agent/*.md` at assertion time, never transcribed into the suite. The **expected** seat set is the file set; `DRIFT-002` asserts equality in both directions so a new agent and a stale seat both fail.
- The declared counts (`24` seats per profile, `24` prompts in the roster, `2` chains, `2` credentials, `2` budgets, `2` profiles, `2` watch targets, `5` new suites plus the extended `doc-conformance`) are asserted exactly and by name, never as floors: a floor cannot detect the regression the pin exists to catch.
- No `mock.module`; no subprocess; no ambient environment read. Every fact is an injected value or a file under a scratch root. The one sanctioned repository write is the build no-op of §4.1 rule 7, which asserts it changed nothing.
- A prompt file is asserted **as data**: line scanning over the roster, never a YAML/behavioural interpretation of prose, so a placeholder rewrite cannot satisfy the scan while leaving an identifier behind.
- Adding a test file needs no suite-map edit: `tests/**` is already in the aggregate `tests` suite, and `DRIFT-007` asserts the committed `verify.suite-map` declaration is unchanged.
- One owner per case: every id appears once in §5.1, once in §5.2 and once in §7.3; an arm that belongs to a case is declared with its owner, never as a second owner.
