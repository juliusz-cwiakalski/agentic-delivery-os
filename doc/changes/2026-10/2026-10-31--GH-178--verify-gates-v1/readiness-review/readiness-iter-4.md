[critical] cross_artifact_consistency / ac_quality / spec_completeness / test_traceability / plan_coverage — `chg-GH-178-spec.md` F-10 (line 180), AC-F10-2 (line 595), AC-F10-3 (line 596), §8.5 (line 379), DEC-18 (line 515); `chg-GH-178-test-plan.md` TC-VGATES-063 precondition (line 1957), step 7 (line 1966), Expected Outcome (line 1970); `chg-GH-178-plan.md` task 5.4 (line 319), task 5.6 (line 321), task 6.3 (line 357), sequencing item 5 (line 50); delivered `packages/cli/src/index.ts` (lines 279–280) and `packages/cli/src/output/serialize.ts` (lines 21–23, 80–84)
   Gap: The artifacts require `verify change` human output to stay byte-identical to today under the shared `humanText` hook, and TC-VGATES-063 step 7 now explicitly plants a secret whose raw form differs from its JSON-escaped form, requires order-equivalence, and requires the secret to be redacted. The chosen design cannot satisfy this. For `target !== "gates"`, the plan has `humanText` return exactly `JSON.stringify(data, null, 2) + "\n"`, and the existing output pipeline then redacts the resulting **string**; `redactString` performs a literal `split(secret).join("[redacted]")`. The pre-change `humanJson` path redacts the **data object** and only then serializes. With a JSON-escaping-sensitive secret (for example one containing `"` or `\`), the raw secret is no longer a contiguous substring of the serialized text, so the new path neither redacts it nor produces the pre-change bytes; the secret remains visible in escaped form. The test's byte-equality and "no unredacted occurrence" assertions therefore fail, and AC-F10-3's byte-identical claim is false for exactly the fixture the new control introduces. The plan also says "no type change is needed" and omits `packages/cli/src/index.ts`/`packages/cli/src/output/serialize.ts` from Phase 5's code areas, so there is no planned owner for the redaction-order fix. Adding the TC-VGATES-063 control has converted iteration-3 Finding 4's untested risk into an explicit, unsatisfiable acceptance test rather than closing it.
   Suggested remediation target phase: specification
   Suggested fix: Keep the `verify change` path on the pre-change redact-then-serialize pipeline. Either (a) make `humanText` return `undefined` for every non-`gates` target and widen the `CommandDefinition.humanText` type to `string | undefined` so `humanJson` handles `verify change`, or (b) change the hook contract so the output pipeline receives the data and redacts it before serialization. If the string-returning hook is retained, narrow TC-VGATES-063 to a non-JSON-escaping secret and remove the order-equivalence/byte-equality claim for escaping-sensitive secrets, recording the residual security risk. Align spec F-10/AC-F10-3/§8.5/DEC-18, plan tasks 5.4/5.6/6.3 (and the Phase 5 file list), and TC-VGATES-063 to the chosen design.
